Bluesky Architecture — ATProto, Repositories, DIDs, Feeds, HLS Video

Decentralised social network: har user ka signed data repository, DID identity, relay/firehose se aggregation, AppView se timeline, labels wala moderation, social proof aur HLS short video.

Centralised Twitter se farak

Bluesky ek open framework ATProto (Authenticated Transfer Protocol) pe bana hai. Data kisi ek company ke DB mein "lock" nahi — har user ka apna repository hai jo kisi bhi compatible server pe host ho sakta hai, aur user apna server badal sakta hai bina followers khoye.

Building blocks

CheezMatlab
RepositoryUser ka signed data store — posts (text + timestamp), follows, likes. Git-jaisa content-addressed structure, har change signed.
DIDDecentralised identifier — permanent user ID; handle (domain name) badal sakta hai, DID nahi.
PDS (personal data server)Jahan repo host hota hai.
Relay / firehoseSaare PDS se updates ka ek stream.
AppViewFirehose padh ke indexes banata hai — likes count, replies, timelines.
flowchart LR
  U1[User repo on PDS 1] --> R[Relay: firehose]

  R --> MOD[Moderation service: labels]
  R --> FG[Custom feed generators]
  AV --> APP[Bluesky app]
  MOD --> APP
  FG --> APP

Features ka design

  • Follow: sirf follow karne wale ke repo mein target ka DID add hota hai. Followers count kahin "stored" nahi — AppView aggregate karta hai.
  • Timeline: user ke posts reverse-chronological; likes/comments repo mein nahi hote, isliye AppView se aate hain.
  • Moderation: moderation service posts pe labels (metadata) lagati hai — auto ya manual; client user preference ke hisaab se hide/blur. Multiple moderation services subscribe kar sakte ho.
  • Social proof: "aapke follow kiye kitne log isko follow karte hain" — graph intersection query.
  • Short video (90s tak): HLS — har quality ~5s segments mein; master playlist (qualities) + media playlist (segments). Client network dekh ke quality chunta hai; CDN cache; stream requests 302 redirect se CDN pe. Views = master playlist requests ka count, watch-time = last fetched segment. Subtitles alag media playlist.
Interview mein kaise bolein

Decentralised design ka sawaal aaye to bolo: "Write path user-owned signed repos mein (PDS), read path aggregated indexes (AppView) se — ye CQRS jaisa split hai. Relay firehose sab changes stream karta hai; counts/timelines derived data hain." Aur HLS master/media playlist ka 2-line explanation.

Key Takeaways

  • User data = signed repository; identity = DID.
  • Writes decentralised, reads aggregated (AppView) — CQRS feel.
  • Counts aur timelines derived data hain, source nahi.
  • Moderation = labels, policy client/user ke haath.
  • HLS: master playlist → media playlist → segments.
