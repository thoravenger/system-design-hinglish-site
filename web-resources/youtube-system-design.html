YouTube System Design — Pre-signed Upload, ABR Streaming, Watch Progress

"App servers sirf metadata, heavy bytes seedha blob storage + CDN" — pre-signed URL upload, resumable 256 GB uploads, manifest + adaptive bitrate, fire-and-forget watch progress aur cursor pagination.

Site pe pehle se (yahan se jodo)
  • Ch 14 · Design YouTube (Alex Xu) — transcoding DAG, CDN cost
  • Web Resources · Spotify (audio version of same idea)

Requirements jo design badalte hain

  • Web + mobile se upload, file 256 GB tak, beech mein toote to resume (data loss nahi).
  • ~1M uploads/day; naya video turant sabko dikhe zaroori nahi — eventual consistency OK.
  • Streaming smooth, har network pe. Search + comments paginated.

Design philosophy

Ek line

Application servers halka metadata sambhalein; bhaari video bytes seedha cloud storage aur CDN se jaayein. App server bandwidth ka bottleneck kabhi na bane.

4 APIs, 4 lessons

APIKya karta haiLesson
POST /v1/videosVideo ID reserve + pre-signed S3 URL returnClient seedha S3 pe upload karta hai (multipart/resumable) — app server untouched
GET /v1/videos/{id}Metadata + manifest file URLManifest batata hai kaunse segments/resolutions hain; client CDN se ABR streaming karta hai
POST /v1/progress/{id}Playback position saveMillions writes/sec — fire-and-forget, high-throughput store (DynamoDB jaisa), consistency se zyada speed
GET /v1/searchSearch index queryCursor pagination (next_cursor) — "skip 10M rows" wali problem nahi
flowchart LR
  C[Client] -->|1 POST videos| API[API servers]
  API -->|pre-signed URL| C
  C -->|2 upload chunks| S3[(Blob storage raw)]
  S3 -->|event| TQ[Transcode queue]
  TQ --> W[Transcoders: 240p..4K + segments + manifest]
  W --> S3B[(Blob storage encoded)]
  S3B --> CDN[CDN]
  C -->|3 GET video| API
  C -->|4 ABR segments| CDN

Adaptive bitrate (ABR) ek minute mein

Video ko kai qualities mein encode karke chhote segments (kuch seconds) mein kaata jaata hai. Manifest (HLS .m3u8 / DASH .mpd) mein list hoti hai. Player network dekh ke har segment ki quality chunta hai — 4G pe 1080p, lift mein 360p, bina buffering.

Note

Free preview API design tak hai. Transcoding pipeline (DAG), CDN cost optimisation aur error handling Ch 14 mein detail mein hai.

Interview mein kaise bolein

"Upload pe app server bytes nahi chhuega — pre-signed URL se client seedha S3 pe resumable multipart upload. Upload complete event pe transcoding queue, workers multiple bitrates + segments + manifest banate hain, CDN serve karta hai. Watch progress fire-and-forget DynamoDB mein. Search cursor-paginated." Ye 4 lines + diagram = solid answer.

Key Takeaways

  • Metadata app server pe, bytes S3/CDN pe.
  • Pre-signed URL + multipart = resumable bade uploads.
  • Manifest + segments = adaptive bitrate.
  • High-volume progress writes: async, eventual.
  • Cursor pagination for search/comments.
