Nginx — Master-Worker, Event Loop, Shared Memory Cache

Thread-per-connection kyun fail hota hai (memory, context switch), aur Nginx ka jawab: master + per-core single-threaded workers, non-blocking event loop (epoll), shared memory cache aur zero-downtime reload.

Purane web servers ki dikkat

  • Resource usage: har connection ke liye alag thread/process — idle connection bhi memory + CPU kha raha hai.
  • Performance: thread blocking I/O pe wait karta hai; hazaron threads = bahut saare context switches (CPU ek thread se doosre pe jaate-jaate time waste).

Yahi famous C10K problem hai — 10K concurrent connections ek server pe.

Nginx ka design

IdeaKaise
Parallelism (kaam ek saath chalana)Master–worker model: master config padhta hai aur workers banata hai; har CPU core pe ek worker. Master privileged kaam karta hai (ports bind, config reload).
Concurrency (kai kaam ek saath manage karna)Har worker single-threaded, non-blocking sockets + event loop (Linux pe epoll): "jo socket ready hai uska kaam karo, warna aage badho". Ek worker hazaron connections.
ScalabilityResponse caching; har worker alag cache rakhe to duplicate — isliye shared memory cache zone sab workers ke beech. Cache loader/manager processes disk cache sambhalte hain.
flowchart TB
  M[Master process: config, bind ports, reload] --> W1[Worker core 1: event loop]
  M --> W2[Worker core 2: event loop]
  M --> W3[Worker core N: event loop]
  W1 <--> SHM[(Shared memory: cache keys, rate-limit zones)]
  W2 <--> SHM
  W3 <--> SHM
  C[Hazaron clients] --> W1
  C --> W2
  • Zero-downtime reload: naye config ke saath master naye workers banata hai, purane workers current requests khatam karke exit — connections drop nahi.
  • Blocking kaam (disk I/O) ke liye thread pools — taaki event loop na ruke.
  • Use cases: reverse proxy, load balancer, static files, TLS termination, cache.
Concurrency ≠ Parallelism

Parallelism = ek hi time pe kai kaam chal rahe (multi-core). Concurrency = kai kaam handle ho rahe, zaroori nahi ek saath chal rahe (ek worker event loop se hazaron connections juggle karta hai). Nginx dono use karta hai.

Interview mein kaise bolein

"Nginx thread-per-connection nahi karta: per-core single-threaded workers, har worker epoll event loop se hazaron non-blocking connections. Kam memory, kam context switches. Shared memory se cache/rate-limit state share. Reload pe naye workers, purane gracefully drain." Concurrency vs parallelism ka farak ek line mein — ye common follow-up hai.

Key Takeaways

  • Thread-per-connection = memory + context switch waste.
  • Master + per-core workers = parallelism.
  • Single-threaded event loop (epoll) = concurrency.
  • Shared memory cache; graceful reload.
