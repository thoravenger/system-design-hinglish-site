ChatGPT Apps — MCP Server + Widget, Trust Boundaries

"Chatbot baat karta hai, app kaam karta hai": Plugins/GPTs se farak, MCP server (tools + UI resources), sandboxed iframe widget with window.openai bridge, aur 4 trust boundaries (CSP, app isolation).

Plugins → GPTs → Apps

Plugins (2023–24)GPTsApps
Kya theAPI wrappers; result text meinCustom instructions + filesTools + interactive UI widget chat ke andar
Dikkat / faydaNative UI nahi, sab textShare karna mushkil, brand control kamMap, booking form, spreadsheet — asli action complete

Example: "restaurant book karo" → bina app ke ChatGPT tareeka batata hai; app ke saath widget mein real availability, menu, time chuno, confirm — booking ho gayi.

Do hisse

flowchart LR
  U[User chat] --> GPT[ChatGPT model]
  GPT -->|tool call over HTTPS| MCP[Your MCP server]
  MCP -->|structured data + ui resource| GPT
  GPT --> W[Widget in sandboxed iframe]
  W -->|window.openai.callTool| MCP
  W -->|only CSP-allowed domains| EXT[External APIs]
  • MCP server = backend. Do cheezein expose karta hai:
    • Tools: name (search_restaurants), description (model isi se decide karta hai kab call kare — vague description = tool kabhi nahi chalega), input schema, output template (kaunsa UI).
    • Resources: UI templates — HTML bundle (aksar single-file React build), ui://widget/restaurant-list.html jaisa URI.
  • Widget = frontend, sandboxed iframe mein. ChatGPT window.openai inject karta hai: read — toolOutput, toolInput, widgetState, theme, locale; actions — callTool(), setWidgetState(), sendFollowUpMessage().

Security: 4 trust boundaries

BoundaryRule
ChatGPT ↔ MCP serverHTTPS; server verify kare ki request sach mein ChatGPT se hai
ChatGPT ↔ WidgetSabse strict: sandboxed iframe, ChatGPT ka DOM/cookies/doosre apps ka data nahi
Widget ↔ External APIsSirf CSP mein declare kiye domains
App ↔ AppHar app alag sandbox — ek doosre ka state/DOM nahi
Design lesson

Apps "quick aur conversational" hone chahiye — poora product export mat karo, sirf wo flows jo chat mein natural hain (search, compare, book).

Interview mein kaise bolein

Agent/tool design ke sawaal mein ye pattern use karo: "Capabilities MCP tools ke roop mein (clear description + JSON schema), UI ek sandboxed widget jo sirf bridge API se baat kare, aur har boundary pe least privilege — HTTPS + origin verification, iframe sandbox, CSP allow-list, per-app isolation."

Key Takeaways

  • Apps = tools + interactive UI, sirf text nahi.
  • MCP server: tools (actions) + resources (UI templates).
  • Tool description hi model ka routing signal hai.
  • Widget sandboxed iframe + window.openai bridge.
  • CSP allow-list aur per-app isolation.
