Pastebin System Design — Metadata vs Content Split

URL shortener jaisa skeleton, par content bada: metadata SQL mein, paste text object storage mein, CDN, paste-ID generation, visibility/permissions aur TTL-based cleanup (DynamoDB stream + Lambda).

Shortener se farak

Dono mein "unique ID → content" mapping hai. Farak: Pastebin ka content bada text (code, config) hai — MBs tak. To DB row mein text daalna galat; metadata aur content alag.

Requirements

  • Paste banao (text) → unique URL; dekho; owner delete kar sake.
  • Expiry optional, visibility (public/private/unlisted), custom ID.
  • Scale (article): ~1M write DAU, ~100 read QPS — chhota hai par design principles same. Read-heavy.

API

  • POST /pastes — non-idempotent (har call naya paste; shortener ke PUT se ulta — kyunki same text do baar paste karna valid hai).
  • GET /pastes/:id, DELETE /pastes/:id (Authorization header se owner check).

Paste ID generation

  • Random ID, hash(IP + timestamp), ya token range counter — shortener wali KGS hi. Custom ID ho to DB/Bloom filter se availability check.
  • KGS pe lock/semaphore taaki ek ID do baar na nikle; KGS active-active/active-passive for availability.

Cleanup — 4 tareeke

  1. Lazy: expired paste khule to tab delete + 404.
  2. Dedicated cleanup service: replica DB se expired dhundho, off-peak mein primary + object storage se hatao.
  3. Timer/TTL: metadata DynamoDB mein TTL ke saath; expire pe DynamoDB Stream → Lambda → object storage se content delete.
  4. 6 mahine se na dekhe pastes archive/delete (cost).

Baaki: consistent hashing se partition (paste ID key — hot shard se bachav), rate limiting (API key / IP), analytics HTTP headers se, monitoring, JWT auth, VPC.

Interview mein kaise bolein

"Metadata aur content ko alag karunga: text object storage + CDN mein, metadata SQL mein. ID ke liye token-range KGS. POST non-idempotent kyunki same text ke do paste valid hain. Expiry ke liye TTL + stream-triggered cleanup." Shortener se compare karke bolo — interviewer ko pattern recognition dikhega.

Key Takeaways

  • Bada content → object storage + CDN; metadata SQL.
  • POST (non-idempotent) vs shortener ka PUT — reason samjho.
  • Same KGS patterns: random, hash, token range, custom.
  • Cleanup: lazy, job, TTL + stream/Lambda, archive.
