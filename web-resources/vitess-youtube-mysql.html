Vitess — YouTube ne MySQL ko kaise scale kiya

Sharding logic app se bahar: VTTablet sidecar har MySQL ke saamne, VTGate stateless query router, aur topology/config ke liye distributed key-value store (ZooKeeper).

YouTube ki 3 dikkatein

ProblemKyun hua
1. ShardingStorage ke liye MySQL partition karna pada → transactions/joins mushkil, aur "kaunsa shard?" ka logic application code mein — complexity har team pe.
2. PerformanceLeader-follower replication mein follower stale data de sakta hai → fresh data chahiye to app ko leader pe route karna padta.
3. ProtectionLambi queries aur bahut saare connections ek saath MySQL ko gira sakte hain.

Vitess = MySQL ke upar abstraction layer

flowchart TB
  APP[App: normal MySQL protocol] --> VG[VTGate: stateless proxy]
  VG --> T1[VTTablet] --> M1[(MySQL shard 1)]
  VG --> T2[VTTablet] --> M2[(MySQL shard 2)]
  VG -.schema, sharding scheme, roles.-> TOPO[(Topology KV store: ZooKeeper)]
  T1 -.-> TOPO
  • VTTablet (sidecar, har MySQL instance ke saath): MySQL control + backups, connection pooling, query rewrite, bure/lambe queries kill, row cache — "protection" problem solve.
  • VTGate (stateless proxy): schema + sharding scheme dekh ke query sahi VTTablet pe route; multi-shard queries scatter-gather. App ko lagta hai ek hi MySQL hai — "sharding" problem solve. Fresh reads leader pe route — "performance" problem.
  • Topology store (ZooKeeper jaisa distributed KV): schemas, sharding scheme, leader/follower roles — config server.
Real world

Vitess open-source hai (CNCF graduated). Slack, GitHub, PlanetScale jaise log MySQL scale karne ke liye ise use karte hain.

Interview mein kaise bolein

Sharding ka sawaal aaye ("MySQL 10 TB ho gaya, kya karoge?") to bolo: "Application ko sharding-aware banane ke bajaye ek proxy layer (Vitess jaisa): stateless router (VTGate) + per-instance sidecar (VTTablet) for pooling/protection + topology store. App MySQL protocol hi bolta hai." Phir resharding aur cross-shard transactions ke trade-offs.

Key Takeaways

  • Sharding logic app se nikaal ke proxy layer mein.
  • VTGate = stateless router; VTTablet = per-MySQL sidecar (pooling, protection).
  • Topology/config ZooKeeper-type store mein.
  • Fresh reads leader pe, baaki replicas pe.
