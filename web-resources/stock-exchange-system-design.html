Stock Exchange System Design — Broker, Gateway, Matching Engine

Farmer's market wali simple analogy se: broker → gateway → matching engine, in-memory order book, price-time priority matching aur deterministic sequencing.

Simple samajh

Exchange ek bazaar hai: har stock ek "stall", buyers aur sellers aate hain, exchange sirf unhe milata hai aur fees kamata hai. Zyada trades = zyada kamai, isliye speed aur fairness sab kuch hai.

Scope (article): sirf stocks; user BUY/SELL order daal sakta hai aur kabhi bhi cancel kar sakta hai; market data real-time dikhe.

Terms jo pata hone chahiye

  • Broker: app/site jahan se user order daalta hai aur price dekhta hai (Zerodha/Robinhood jaisa).
  • Order book: ek stock ke saare open BUY aur SELL orders — kaun, kitna, kis price pe.
  • Limit order: "is price ya better pe hi". Market order: "jo best price abhi hai".

Architecture — critical path

Broker→Gateway (validate, convert, rate-limit)→Sequencer→Matching engine (order book)→Market data + execution reports
  • Gateway: broker ke orders ko exchange ke internal format mein badalta hai, results wapas bhejta hai. Low latency ke liye co-location — broker ke servers exchange ke paas.
  • Matching engine: sequence numbers verify, BUY/SELL match, aur trades se market data banata hai.
  • Order book in-memory: har symbol ke liye do lists — BUY (highest price pehle) aur SELL (lowest price pehle); same price pe pehle aaya pehle (price-time priority).

  Q -- haan --> M[Trade execute, quantity ghatao]

Matching ka golden rule

Match tab jab buy price ≥ sell price. Aur same input sequence → hamesha same output — matching function deterministic hona chahiye. Isi se: replay karke state rebuild, primary/backup engines exact same state mein, audit possible.

Note

Is article ka free preview yahan tak hai. Event sourcing, risk checks, market data fan-out aur hot-standby ke details ke liye site ka Chapter 28 dekho — wahan poora deep dive Hinglish mein hai.

Interview mein kaise bolein

Do cheezein zaroor bolo: (1) matching engine single-threaded + in-memory order book per symbol, kyunki locks latency badhate hain; (2) sequencer har order ko number deta hai aur engine deterministic hai, isliye event log replay se recovery. Phir latency: co-location, kernel-bypass networking, DB critical path se bahar.

Key Takeaways

  • Critical path: broker → gateway → sequencer → matching engine.
  • Order book in-memory; price-time priority.
  • Match condition: buy ≥ sell.
  • Determinism + sequence numbers = replay, failover, audit.
