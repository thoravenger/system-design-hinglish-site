Case study #8 · 🎬 Media, Social & Frontend

Spotify System Design — Metadata DB + Blob Storage + Signed URLs

500K users, 30M songs: storage estimate (~90 TB raw), stateless API layer, JWT, signed URLs, HTTP range requests + HLS/DASH se audio streaming aur play analytics.

Free preview + paid part
Site pe pehle se (yahan se jodo)
  • Ch 14 · Design YouTube (video streaming)
  • Web Resources · YouTube

Scope aur estimate

Users  ≈ 500K,  songs ≈ 30M
Avg song ≈ 3 MB  → 30M × 3 MB ≈ 90 TB raw audio
+ multiple bitrates, replicas across regions, re-upload versions → kai guna
Metadata (title, artist, album, duration…) ≈ chhota — GBs mein

Seekh: audio bytes aur metadata ka size ratio bahut alag — dono ke liye alag storage.

Components

  1. Mobile app: UI, search, playback state, playlists; metadata REST se, audio seedha storage/CDN se.
  2. Load balancer: round-robin / least-connections, har ~30s health check, unhealthy hatao.
  3. Stateless API servers: JWT validate, metadata DB query, signed URL generate — horizontally scale.
  4. Blob storage (S3 jaisa): /artist/album/song.ogg layout, signed URLs jo kuch ghanton mein expire. Multi-region replication. HDFS alternative, par managed blob storage zyada simple/reliable.
  5. Metadata DB: SQL (relations: artist → album → song, playlists).

Play dabane pe kya hota hai

sequenceDiagram
  participant A as App
  participant API as API server
  participant DB as SQL metadata
  participant S as Blob storage / CDN
  A->>API: GET /songs/{id} + JWT
  API->>DB: song metadata
  API-->>A: metadata + signed URL
  A->>S: range requests (HLS/DASH chunks)
  S-->>A: audio chunks
  A->>API: POST /songs/{id}/play (analytics, periodic)
  • Range requests: poori file nahi, bytes ke tukde — seek karna aur slow network pe start fast.
  • HLS/DASH: bitrate auto switch, har device pe support.
  • Upload (artist) path: file storage mein, metadata DB mein, phir transcode to multiple bitrates (free preview yahin tak).
Blob storageTrade-off
PlusAlmost unlimited scale, durability built-in, bade files ke liye sasta
MinusLocal disk se zyada latency, egress cost — isliye CDN + client cache
Interview mein kaise bolein

"Metadata SQL mein, audio blob storage mein; API stateless aur sirf signed URL deta hai, audio client CDN/storage se range requests + HLS/DASH se kheenchta hai. Popular songs CDN edge pe, offline mode ke liye encrypted client cache." Estimation (90 TB) bolna mat bhoolna — scale ka sense dikhata hai.

Key Takeaways

  • Bytes vs metadata: alag stores.
  • Signed URLs = storage public kiye bina secure direct access.
  • Range requests + adaptive streaming.
  • Stateless API + LB health checks = easy scale.
