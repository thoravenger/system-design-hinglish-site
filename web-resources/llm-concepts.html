Ek line mein

LLM ek bahut bada next-token predictor hai — pattern-matcher, truth ka source nahi. Article 33 concepts ko 7 layers mein baandhta hai; neeche wahi map, Hinglish mein.

1. Andar ki machinery

ConceptSeedhi baat
TokenText ka tukda (word/sub-word). Pricing, context limit sab tokens mein.
EmbeddingToken/text ka number-vector; similar meaning → paas-paas vectors.
Latent spaceWo high-dimensional "map" jisme meanings rehte hain.
ParametersModel ke learned weights (billions) — model ka "knowledge".

2. Training aur behaviour shaping

Pre-training (internet text, next token)→Base model→Instruction tuning / Fine-tuning→Alignment: RLHF→Instruct / chat model
  • Base model text complete karta hai; instruct model instructions follow karta hai.
  • Fine-tuning: specific data pe aage train (domain, style).
  • RLHF: humans answers rank karte hain → reward model → model ko helpful/safe direction mein push.

3. Baat kaise karein (interaction layer)

  • System vs user prompt: system = rules/persona, user = sawaal.
  • Context window: ek baar mein kitne tokens dekh sakta hai (prompt + history + docs + output).
  • Zero-shot vs few-shot: bina example vs prompt mein kuch examples.
  • Chain-of-thought: step-by-step sochwana → reasoning better.

4. Real time mein (inference)

  • Inference = trained model se output nikaalna, token by token. Latency = time-to-first-token + tokens/sec.
  • Temperature: low = deterministic/focused, high = creative/random (stochastic).

5. Basics se aage: grounding, RAG, agents

flowchart LR
  Q[User question] --> E[Embed query]
  E --> VDB[(Vector DB)]
  VDB -->|top-k chunks| P[Prompt: question + context]
  P --> LLM[LLM]
  LLM --> A[Grounded answer + citations]
  • Grounding: answer ko trusted data se baandhna. RAG = retrieve relevant docs → prompt mein daalo → generate.
  • Workflow vs agent: workflow = fixed steps code mein; agent = LLM khud decide kare next step/tool. Agentic AI = multi-step planning + tool use + memory.

6. Model flavours

  • Proprietary (API se) vs open-weight/open-source (self-host, control, cost).
  • API = app aur model ka connection. SLM (<~15B params) = sasta, fast, edge pe.
  • Multimodal = text + image + audio. Reasoning models = jawab se pehle "notes" banate hain, multi-step problems ke liye.

7. Evaluation aur failures

FailurePatch
Hallucination (confident jhooth)Grounding/RAG + citations
Math/logic weakTools (calculator, code exec), reasoning models
Inherited biasCurated data, alignment, evals
Knowledge cutoffRAG / web search tools
Unsafe outputGuardrails: input + output dono filter

Benchmarks model ki raw capability compare karte hain; metrics (faithfulness, relevance) aapke app pe; scale pe LLM-as-judge — ek model doosre ke answers grade kare (rubric ke saath, human spot-checks zaroori).

Interview mein kaise bolein

GenAI round mein ye flow bolo: "LLM next-token predictor hai; pre-training → instruct tuning → RLHF. App banate waqt hallucination aur cutoff ke liye RAG se grounding, math ke liye tools, safety ke liye guardrails, aur quality ke liye offline evals + LLM-as-judge." Workflow vs agent ka farak zaroor poocha jaata hai.

Key Takeaways

  • Token → embedding → latent space → parameters.
  • Pre-train → fine-tune → RLHF = chat model.
  • Context window + temperature = runtime knobs.
  • RAG/grounding hallucination aur cutoff ka main ilaaj.
  • Workflow (fixed) vs agent (LLM decides).
  • Evaluate: benchmarks, app metrics, LLM-as-judge.
