Real-Time Leaderboard — Redis Sorted Sets (ZSET) Deep Dive

Top-10, meri rank, mere aas-paas ke players, daily/weekly boards, friends leaderboard — sab Redis sorted set se; ZSET andar se hash + skip list kyun hai, aur sharding kaise.

Kyun SQL kaafi nahi

Chhote scale pe ORDER BY score DESC LIMIT 10 + cache-aside chal jaata hai. Lekin "meri rank kya hai" = count of players with higher score → har baar bada scan. Read:write ≈ 5:1 (article) — kaafi write-heavy. Isliye in-memory sorted set.

ZSET commands — interview cheat sheet

KaamCommandComplexity
Score badhaoZINCRBY lb 50 player42O(log N)
Top 10ZREVRANGE lb 0 9 WITHSCORESO(log N + 10)
Meri rank / scoreZREVRANK lb player42, ZSCOREO(log N) / O(1)
Aas-paas ke playersrank r nikaalo → ZREVRANGE lb r-5 r+5O(log N + k)

Andar kya hai: ZSET = hash map (member → score, O(1) lookup) + skip list (score order mein, O(log N) insert/rank). Skip list = multiple levels wali linked list jisme upar ke levels "express lane" hain.

Variations

  • Daily/weekly/monthly: alag ZSET per period (lb:2026-10-27), purane pe TTL.
  • Global vs per-game: per-scenario ZSET + aggregated global ZSET (ZUNIONSTORE).
  • Friends leaderboard: friend list ka chhota ZSET banao aur scores se intersect (ZINTERSTORE).
  • Historical: completed games REST + long TTL cache; live games WebSocket se push.
  • Push notifications: DB change feed/trigger se "aapka score beat ho gaya".

Scale: sharding

ApproachPlusMinus
Score-range sharding (fixed partitions)Top-N sirf highest shard sePlayers shards ke beech move karte hain; hot shard
Hash/consistent hashing (Redis Cluster hash slots)Even distributionTop-N/rank ke liye scatter-gather — sab shards se poochho, merge karo
  • Concurrency: reverse proxy pe collapsed forwarding (same concurrent reads ek hi baar backend pe); Redis single-threaded hai to ek command atomic.
  • Durability: ZSET cache hai — truth DB (ya DynamoDB) mein, async write; Redis replicas + persistence.
  • Security: fake score updates rokne ke liye scores server-side compute, signed requests, rate limiting.
Interview mein kaise bolein

Seedha bolo: "Redis sorted set — ZINCRBY update, ZREVRANGE top-10, ZREVRANK meri rank, sab O(log N)." Phir internals (hash + skip list), phir scale (score-range vs hash sharding + scatter-gather) aur durability (DB source of truth). Ye 3 layer answer interviewer ko pasand aata hai.

Key Takeaways

  • Leaderboard = ZSET; rank queries O(log N).
  • ZSET = hash + skip list.
  • Period/friends/global boards = alag ZSETs + union/intersect.
  • Sharding: score-range (easy top-N) vs hash (scatter-gather).
  • Redis cache hai; DB source of truth; scores server-side validate.
