Vector Database — Storage (Quantization), Index (HNSW), Query Path

B-tree exact match ke liye hai, embeddings "closeness" maangte hain. Teen layers: storage (6 KB/vector, scalar/binary quantization), index (HNSW small-world graph) aur query path — cost, latency, accuracy ka trade-off.

Normal DB kyun nahi

WHERE user_id = 12345 ya date range — B-tree index seedha row pe le jaata hai. Embedding ke saath koi "exact value" nahi; chahiye sabse paas ke vectors (cosine / dot product / L2) high-dimensional space mein. Har vector se compare (brute force) = O(N·d) — millions pe slow. Isliye ANN (approximate nearest neighbour) indexes.

Layer 1: Storage — vectors bhaari hain

1 vector = 1536 dims × 4 bytes (float32) ≈ 6 KB
10M vectors ≈ 60 GB  (sirf raw vectors; index alag)
QuantizationKyaSavingCost
Scalar (int8)Har dimension 32-bit → 8-bit~4×Thoda accuracy loss
BinaryHar dimension 1 bit~32×Zyada loss; aksar re-rank ke saath
Product quantizationVector ko sub-vectors mein tod ke codebookBahut zyadaComplex, approximation error

Approximation error = compressed aur original ka gap → kabhi-kabhi ek sahi result miss (recall girta hai).

Layer 2: Index — HNSW

"Small world" idea: duniya mein kisi tak bhi kuch hi connections mein pahunch jaate ho. HNSW multi-layer graph banata hai: upar ki layer mein kam nodes, lambi "express" links; neeche sab nodes, chhoti links. Query upar se shuru → greedy closest neighbour ki taraf → layer neeche → bottom pe best matches.

flowchart TB
  L2[Layer 2: few nodes, long jumps] --> L1[Layer 1: more nodes]
  L1 --> L0[Layer 0: all vectors, local links]
  Q[Query vector] -.enter top.-> L2
  L0 --> R[top-k nearest]
  • Knobs: M (har node ke links), efConstruction, efSearch — zyada = better recall, zyada memory/latency.
  • Alternatives: IVF (clusters), DiskANN (disk-based) — memory vs latency trade-off.

Layer 3: Query path

Text query→Embedding model→Metadata filter (tenant, date)→ANN search (HNSW)→Re-rank (exact / cross-encoder)→top-k to app / LLM

Interview mein kaise bolein

"Embeddings ke liye exact-match index kaam nahi karta — ANN chahiye. Main HNSW lunga (high recall, in-memory), memory bachane ke liye int8/PQ quantization + exact re-rank top candidates pe. Metadata filter pehle/saath, aur recall@k vs p99 latency tune karunga ef/M se." Storage math (6 KB × N) bolna impressive lagta hai.

Key Takeaways

  • Embeddings = closeness search, exact match nahi.
  • 1536-d float32 ≈ 6 KB per vector — memory math karo.
  • Quantization: 4×+ saving, thoda recall loss.
  • HNSW = multi-layer small-world graph; ef/M knobs.
  • Query: embed → filter → ANN → re-rank.
