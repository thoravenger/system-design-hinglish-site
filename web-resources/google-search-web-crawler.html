Google Search ka Web Crawler — URL Frontier, Dedup, Politeness

Search = crawler + search engine. Crawler side: seed URLs, Mercator-style two-stage frontier (priority + politeness), URL aur content dedup (fingerprints), robots.txt, canonical links, storage aur orchestration vs choreography.

Site pe pehle se (yahan se jodo)
  • Ch 09 · Design a Web Crawler (Alex Xu)
  • Ch 13 · Search Autocomplete

Scale estimate

Active websites ≈ 200M × ~50 pages ≈ 10B pages to crawl
Searches/day ≈ 8.5B  → ~100K searches/sec

Do subsystems: web crawler (pages download + store) aur search engine (index banao + queries serve). Crawler ka kaam page store hote hi khatam; indexing search engine ka.

URL frontier — Mercator style, do stage

flowchart LR
  IN[Naye URLs] --> PR[Prioritizer]
  PR --> F1[Front queue high]
  PR --> F2[Front queue low]
  F1 --> SEL[Front selector: priority ke hisaab se]
  F2 --> SEL
  SEL --> RT[Router: host to back queue]
  RT --> B1[Back queue: host A]
  RT --> B2[Back queue: host B]
  B1 --> H[Min-heap: next allowed fetch time per host]
  B2 --> H
  H --> DL[Downloader workers]
  • Front queues = priority (PageRank, freshness, update frequency).
  • Back queues = politeness — ek queue ek host; heap batata hai kis host ko kab dobara hit kar sakte hain. Ek site pe hammer nahi.

Storage

  • Raw HTML (as-is) object storage mein, ya parsed text — trade-off: re-processing flexibility vs space.
  • Metadata: URL, content location, last crawled, status, fingerprint — key-value / wide-column store.

Loop: frontier → DNS resolve (cache!) → fetch → shared JS/CSS cache → parse + link extract → filters (blocklist, URL patterns, region) → wapas frontier.

Note

Free preview crawler tak hai; search engine (inverted index, ranking) wala hissa paid.

Interview mein kaise bolein

"Frontier do-stage: front queues priority ke liye, back queues per-host politeness ke liye + heap for next-fetch time. Dedup do level pe: URL (normalize + Bloom filter) aur content (fingerprint). robots.txt aur canonical respect. Components event-driven ya orchestrated — retries ke liye orchestration." Ch 09 ke saath padho.

Key Takeaways

  • Search = crawler + indexer/search engine.
  • Frontier: priority (front) + politeness (back, per host).
  • URL dedup + content fingerprint dedup.
  • robots.txt, canonical, DNS cache.
  • Sync vs choreography vs orchestration trade-offs.
