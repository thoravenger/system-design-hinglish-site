    Basic Mid Senior

    HLD: stream high level pe kaise kaam karta hai

    Pehle bada picture. Interview me HLD ka matlab hai: kaunse components hain, data kaise behta hai, aur kaunsa kaam kab execute hota hai.

    Q1Stream asal me hai kya?

    Stream data store nahi karta. Yeh ek pipeline ka plan hai jo kisi source (List, array, file, generator) se data kheench kar steps se guzaarta hai. Teen hisse hote hain: Source, intermediate ops (0 ya zyada) aur exactly ek terminal op.

    SourceList, array, Files.lines(), Stream.iterate()
    SpliteratorElement nikaalta hai (tryAdvance) aur kaam baantta hai (trySplit)
    Stateless opsfilter, map, flatMap, peek, mapMulti. Har element akela decide hota hai.
    Stateful opssorted, distinct, limit, skip, takeWhile, gather. Doosre elements ki yaad chahiye.
    Terminal optoList, collect, reduce, forEach, count, findFirst. Yahin se execution shuru.
    • Lazy: intermediate ops sirf plan banate hain. Kaam terminal op pe shuru hota hai.
    • Single-use: ek stream ek hi baar consume hoti hai.
    • Non-interfering: pipeline chalte waqt source ko modify nahi karna. Result naya banta hai.
    • Infinite bhi ho sakti hai: iterate/generate se. Short-circuit ops (limit, findFirst, takeWhile) use khatam karte hain.
    • Sequential ya parallel: code same rehta hai, sirf parallel() ka switch.

    Q2Data kaise flow hota hai: ek-ek element ya poora batch?

    Ek-ek element, poori pipeline se. Element "a" filter, map aur forEach tak jaata hai, tab jaake "b" shuru hota hai. Ise vertical ya fused processing kehte hain: beech me koi temporary list nahi banti. Exception sirf stateful ops hain jaise sorted(), jo pehle sab elements jama karte hain.

    Q3Lazy aur single-use ka proof?

    Terminal op ke bina ek bhi lambda nahi chalta. Aur ek stage ko dobara use karo to exception aata hai, kyunki har stage object pe linkedOrConsumed flag set ho jaata hai (LLD Q2 dekho).

    Q4Parallel high level pe kaise chalta hai?

    Spliterator trySplit() se data ko tukdon me baantta hai. Har tukda ForkJoin common pool ke kisi thread pe same pipeline sequentially chalata hai. End me partial results combiner se judte hain. Isliye lambdas stateless aur operations associative hone chahiye.

    Q5Java 8 se 24 tak architecture me kya badla?

    Core design wahi hai: Spliterator, stages ki linked list, aur Sink chain. Badlaav naye operations aur kuch behaviour me hain:

    1. Java 9 takeWhile/dropWhile naye stateful ops ke roop me aaye. Aur count() SIZED source pe pipeline skip kar sakta hai (topic #12).
    2. Java 10 flatMap ab short-circuit respect karta hai. Java 8 me findFirst() ke saath bhi inner stream poori chalti thi, aur infinite inner stream pe hang (JDK-8075939, 8u222 me backport).
    3. Java 16 toList() array se seedha unmodifiable list banata hai. mapMulti push-style op hai jo inner stream nahi banata.
    4. Java 21 Sequenced collections ke reversed() views aaye. Virtual threads ne "I/O ke liye parallel stream" wala decision hi badal diya.
    5. Java 24 gather() se naya GathererOp stage aaya: ab apne khud ke intermediate ops likh sakte ho.

    LLD: andar ki classes aur code

    Ab zoom in. Neeche ka JDK code JDK 25 source se liya gaya hai (thoda chhota karke), taaki interview me "andar kya hota hai" confidently bata sako.

    Q1Andar kaunsi classes hain?

    Yaad rakhne ka tareeka: Pipeline plan SAVE karta hai, Sink data UPDATE karta hai, Spliterator data deta hai, TerminalOp sab chalata hai.

    Q2Stages kaise SAVE aur link hote hain?

    Har intermediate op (filter, map…) ek naya stage object banata hai. Constructor pichhle stage ko "consumed" mark karta hai aur doubly linked list banata hai. Yahi single-use ka asli reason hai.

    Q3Sink chain kaise banti hai?

    Terminal op aane pe wrapSink() terminal se source ki taraf (ulta) chalta hai. Har stage apna Sink banata hai jo downstream Sink ko pakad ke rakhta hai. filter ka Sink sirf "pass ya stop" karta hai, aur map ka Sink value badal ke aage deta hai.

    Q4Execution: data kaise push aur UPDATE hota hai?

    copyInto() teen kaam karta hai: begin(size), har element pe accept(), aur end(). Short-circuit op ho to har element se pehle cancellationRequested() check hota hai.

    Q5Flags se kaunse optimizations milte hain?

    Har stage apne bit-flags (StreamOpFlag) pichhle stage ke flags ke saath combine karta hai. JDK in flags ko dekh kar kaam skip kar deta hai:

    FlagKahan se aata haiKya fayda
    SIZEDArrayList, array, IntStream.rangecount() pipeline skip kar deta hai (Java 9+). toArray() exact size ka array banata hai.
    SORTEDTreeSet, sorted() ke baadNatural order wala sorted() no-op ban jaata hai.
    DISTINCTHashSet, distinct() ke baaddistinct() no-op ban jaata hai.
    ORDEREDList, array (HashSet nahi)unordered() se hata do to parallel distinct/limit saste ho jaate hain.
    SHORT_CIRCUITfindFirst, anyMatch, limit, takeWhileCancel-aware loop (forEachWithCancel) chalta hai.

    Q6Collector andar se kaisa hota hai?

    Collector<T, A, R> = 4 functions + characteristics. S-A-C-F yaad rakho: Supplier, Accumulator, Combiner, Finisher. Neeche apna khud ka collector hai, proper naam ke saath:

    Characteristics: IDENTITY_FINISH (container hi result hai, finisher skip), UNORDERED (order ki parwah nahi), CONCURRENT (kai threads ek hi container me add kar sakte hain, jaise groupingByConcurrent).

    Q7Gatherer (Java 24) andar se kaisa hota hai?

    Gatherer = pipeline ke beech ka Collector. I-I-C-F: Initializer, Integrator, Combiner, Finisher. Farak yeh hai ki yeh aage elements push kar sakta hai (0, 1 ya many), aur false return karke stream ko rok bhi sakta hai.

    Q8Parallel me split size kaise decide hota hai?

    Common pool ki default parallelism = availableProcessors() - 1 (minimum 1). Ise system property java.util.concurrent.ForkJoinPool.common.parallelism se badal sakte ho. sorted() parallel me full barrier hai: poora upstream array me collect hota hai, phir Arrays.parallelSort.

    Q9Apne project me stream code ka LLD kaisa rakhein?

    1. Method ka naam intent bataye (findActiveHighEarnerNames). Stream uska implementation detail hai.
    2. Ek line, ek operation. Method reference jahan readable ho (Employee::name).
    3. 3+ line ka lambda private named method me nikaalo (isEligibleForBonus(employee)).
    4. Lambdas stateless aur non-interfering: source modify mat karo, bahar ka mutable state mat chhuo.
    5. Side effects sirf forEach me. peek sirf debugging ke liye.
    6. Public API se Stream return mat karo (single-use trap). List/Set do, ya docs me saaf likho.
    7. Checked exceptions ke liye helper method banao jo wrap kare (topic #20 ka awaitResult).
    8. Numbers ke liye primitive streams. Paise ke liye BigDecimal, double nahi.
    9. 6–7 ops se lambi pipeline ko meaningful variables ya methods me todo.
    10. Performance ka claim JMH se measure karke hi karo, andaaze se nahi.

    Kaise decide karein: kaunsa API kab

    Sawaal ka jawab do, answer milega. Har answer ke saath minimum Java version bhi dikhega.

    Saare decisions ek list me

      Kaise pata karein kaunsa API kis version me aaya?

      1. Javadoc ka @since

      Har method ke Javadoc me "Since: 16" jaisa likha hota hai. Is page ke saare version claims isi tarah JDK 25 source ke @since tags se check kiye gaye hain.

      2. javac --release

      Build ko target version pe compile karo. Naya API use kiya to compile error milega, production me surprise nahi.

      3. Build tool me version lock karo

      Maven ya Gradle me release/toolchain set karo, taaki poori team same API level pe rahe.

      4. jshell me turant try karo

      Java 9+ ke saath jshell aata hai. Koi bhi API ek line me try karo, project banaye bina.

      5. IDE language level

      IntelliJ me project language level (jaise 17) set karo, naye APIs pe warning milegi. Quick Documentation (Win/Linux: Ctrl+Q, macOS: F1) method ka "Since" dikhata hai.

      6. Java Almanac

      javaalmanac.io pe do versions ke beech API diff dekh sakte ho, jaise 17 vs 21. Upgrade planning me kaam aata hai.
