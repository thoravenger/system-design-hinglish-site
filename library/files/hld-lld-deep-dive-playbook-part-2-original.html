DSA Sorting — Deep Dive

Selection vs bubble, merge sort, aur saare sorting mechanisms ka internal working + complexity.

🔢 int[] x = {1,9,2,5,3,4} — Selection vs Bubble?

Theoretical: Dono O(n²). Lekin selection sort hamesha n(n-1)/2 comparisons karta hai, aur swaps sirf O(n) — jab swaps costly ho (bade objects), selection better.

Practical (is array pe): n=6 chhota hai, farq negligible. Bubble sort early-exit (already sorted detection) ke saath best case O(n) de sakta hai. Selection sort nahi.

Real answer: Dono ko chhodo — Arrays.sort() use karo (Dual-Pivot Quicksort, O(n log n)). Interview mein yeh bolo aur justify karo.

Selection vs Bubble — side by sideJAVA
// Selection sort — min nikaal ke aage rakho, O(n²) always
void selectionSort(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        int min = i;
        for (int j = i + 1; j < a.length; j++)
            if (a[j] < a[min]) min = j;         // find min index
        int t = a[i]; a[i] = a[min]; a[min] = t; // 1 swap per pass
    }
}

// Bubble sort with early exit — best case O(n)
void bubbleSort(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < a.length - 1 - i; j++) {
            if (a[j] > a[j+1]) {
                int t = a[j]; a[j] = a[j+1]; a[j+1] = t;
                swapped = true;
            }
        }
        if (!swapped) break;                    // already sorted — O(n)
    }
}

for (i = 0; i < n-1; i++)n-1 passes. Har pass mein ek element apni final position pe settle hota hai.
int min = iCurrent position ko min maan lo. Har pass mein isse better mile toh update.
if (a[j] < a[min]) min = jLinear scan — hamesha poore remaining array ko dekhta hai. Isliye selection sort best case bhi O(n²) hai.
swap a[i] ↔ a[min]Sirf 1 swap per pass. Total O(n) swaps. Jab swap costly ho (large objects), yeh advantage hai.
bubble: swapped flagEarly exit. Agar ek pass mein koi swap nahi hua, array sorted hai — break. Best case O(n).
inner loop: n-1-iHar pass ke baad last i elements sorted hote hain — unhe dobara check nahi karte.

🔀 Merge Sort — Internal Working + Complexity

Merge sort: Divide and conquer. Array ko mid se do halves mein todo, recursively sort karo, phir merge karo.

  • Time: O(n log n) — best, average, worst sab mein (predictable)
  • Space: O(n) auxiliary (arrays), O(log n) recursion stack
  • Stable: Haan — equal elements ka relative order preserve
  • In-place: Nahi (standard version)
  • External sorting: Sequential disk access friendly — massive files ke liye ideal
MergeSort.javaJAVA
void mergeSort(int[] a, int lo, int hi) {
    if (lo >= hi) return;                  // base case: 0/1 element
    int mid = lo + (hi - lo) / 2;            // avoid overflow
    mergeSort(a, lo, mid);
    mergeSort(a, mid + 1, hi);
    merge(a, lo, mid, hi);
}

void merge(int[] a, int lo, int mid, int hi) {
    int[] tmp = new int[hi - lo + 1];
    int i = lo, j = mid + 1, k = 0;
    while (i <= mid && j <= hi)
        tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];  // <= keeps stable
    while (i <= mid) tmp[k++] = a[i++];             // leftover left
    while (j <= hi)  tmp[k++] = a[j++];             // leftover right
    System.arraycopy(tmp, 0, a, lo, tmp.length);
}
LineExplanation
if (lo >= hi) returnBase case. 0 ya 1 element already sorted.
mid = lo + (hi-lo)/2Overflow-safe. (lo+hi)/2 large arrays pe overflow karta.
mergeSort(lo, mid), mergeSort(mid+1, hi)Recursive halves. Depth = log n → O(log n) stack.
int[] tmpAuxiliary array. Merge ke liye O(n) space. In-place merge possible but complex.
a[i] <= a[j]<= for stability. Equal elements pe left se lo — relative order preserve. < hota toh unstable.
while (i <= mid) / while (j <= hi)Ek side khatam, dusri ka leftover copy karo.
System.arraycopyOptimized native copy — loop se faster.

🔄 Rotate Array by K Positions

Best approach: Reversal algorithm — O(n) time, O(1) space. Teen baar reverse karo.

RotateArray.javaJAVA
void rotate(int[] a, int k) {
    int n = a.length;
    if (n == 0) return;
    k = ((k % n) + n) % n;              // handle negative & > n
    reverse(a, 0, n - 1);           // step 1: whole array
    reverse(a, 0, k - 1);           // step 2: first k
    reverse(a, k, n - 1);           // step 3: remaining
}

void reverse(int[] a, int i, int j) {
    while (i < j) {
        int t = a[i]; a[i++] = a[j]; a[j--] = t;
    }
}
LineExplanation
k = ((k % n) + n) % nNormalize k. k=15, n=7 → k=1. Negative k bhi handle (−3 → 4).
reverse(a, 0, n-1)Poora array ulta karo. [1,2,3,4,5] → [5,4,3,2,1].
reverse(a, 0, k-1)Pehle k elements ko wapas ulta. [5,4] → [4,5].
reverse(a, k, n-1)Baaki ko wapas ulta. [3,2,1] → [1,2,3]. Result: [4,5,1,2,3].
🔑 Key Answer

Complexity: O(n) time (2n swaps ≈ n operations), O(1) space. Alternatives: extra array copy (O(n) space), juggling algorithm (GCD-based, also O(n)/O(1)).

🔢 Count Repeating Elements in a List

RepeatingCount.javaJAVA
// Distinct values that repeat (e.g. [a,b,a,c,b,b] → {a,b} → 2)
long repeatingCount(List<String> list) {
    return list.stream()
        .collect(Collectors.groupingBy(x -> x, Collectors.counting()))
        .values().stream()
        .filter(c -> c > 1)
        .count();
}

// Total extra occurrences (e.g. [a,a,a] → 2 extra)
long totalRepeats(List<String> list) {
    Map<String, Long> freq = list.stream()
        .collect(Collectors.groupingBy(x -> x, Collectors.counting()));
    return freq.values().stream().mapToLong(c -> c - 1).sum();
}
🔑 Key Answer

O(n) time, O(k) space where k = distinct elements. HashMap se frequency count — sabse simple aur efficient. Sorting se bhi ho sakta (O(n log n)) but unnecessary.

🧠 HashMap Implementation — Time/Space + Correctness

Typical implementation: Array of buckets + chaining.

  • Resize: O(n) amortized O(1) per op — load factor 0.75 pe double
  • Space: O(n) — buckets + entries
  • Java 8+: Long chains red-black tree mein convert (threshold 8) — worst case O(log n)

Correctness checks: equals/hashCode contract (equal objects → equal hash), rehashing during resize, tombstone handling (open addressing), concurrent modification.

DSA Graph Algorithms — Cycles + SCC

🔁 Detect Cycle in Directed Transfer Graph

Approach: DFS with 3 colors — WHITE (unvisited), GRAY (in progress), BLACK (done). GRAY node pe wapas aana = back edge = cycle.

CycleDetect.javaJAVA
enum Color { WHITE, GRAY, BLACK }

boolean hasCycle(Map<String, List<String>> g) {
    Map<String, Color> color = new HashMap<>();
    for (String s : g.keySet()) color.put(s, Color.WHITE);

    for (String s : g.keySet())
        if (color.get(s) == Color.WHITE && dfs(s, g, color))
            return true;
    return false;
}

boolean dfs(String u, Map<String, List<String>> g,
            Map<String, Color> color) {
    color.put(u, Color.GRAY);
    for (String v : g.getOrDefault(u, List.of())) {
        if (color.get(v) == Color.GRAY) return true;   // back edge
        if (color.get(v) == Color.WHITE && dfs(v, g, color)) return true;
    }
    color.put(u, Color.BLACK);
    return false;
}
LineExplanation
Color { WHITE, GRAY, BLACK }3 states. GRAY = current DFS path mein hai. BLACK = explore ho chuka.
color.put(s, WHITE)Sab unvisited init.
if (color.get(v) == GRAY) return trueBack edge! Current DFS stack mein jo node hai, usse dobara visit = cycle.
color.put(u, BLACK) at endNode fully explored. Ab koi cycle isse hoke nahi jaayegi.
🔑 Key Answer

O(V + E) time, O(V) space. Undirected graph mein union-find ya DFS with parent-tracking. Directed mein 3-color DFS sabse clean. Cycle return karna ho toh parent map maintain karo.

🔗 Find SCCs — Tarjan's Algorithm

Tarjan.javaJAVA
class Tarjan {
    int time = 0;
    Map<String, Integer> disc = new HashMap<>(), low = new HashMap<>();
    Deque<String> stack = new ArrayDeque<>();
    Set<String> onStack = new HashSet<>();
    List<List<String>> sccs = new ArrayList<>();

    void dfs(String u, Map<String, List<String>> g) {
        disc.put(u, time); low.put(u, time); time++;
        stack.push(u); onStack.add(u);

        for (String v : g.getOrDefault(u, List.of())) {
            if (!disc.containsKey(v)) {
                dfs(v, g);
                low.put(u, Math.min(low.get(u), low.get(v)));
            } else if (onStack.contains(v)) {
                low.put(u, Math.min(low.get(u), disc.get(v)));
            }
        }

        if (low.get(u).equals(disc.get(u))) {
            List<String> comp = new ArrayList<>();
            String w;
            do { w = stack.pop(); onStack.remove(w); comp.add(w); }
            while (!w.equals(u));
            sccs.add(comp);
        }
    }
}
LineExplanation
disc.put(u, time); low.put(u, time)Discovery time + low-link. low = sabse chhota disc jo u se reachable (back edges ke through).
stack.push(u); onStack.add(u)Current SCC candidates. onStack set for O(1) check.
if (!disc.containsKey(v)) dfs(v,g)Unvisited — recursive call, phir low update.
else if (onStack.contains(v))Back edge to current SCC. low[u] = min(low[u], disc[v]).
low.get(u).equals(disc.get(u))Root of SCC. Isse stack pop karo jab tak u na mile — poora SCC.
🔑 Key Answer

Tarjan's: O(V+E) single DFS. Alternative: Kosaraju's — 2 DFS passes (transpose graph pe second pass). Tarjan ek hi pass mein kaam kar deta.

Use: Circular dependency detection, deadlock detection, financial transaction clusters.

JVM GC Latency — Diagnose + Tune

Diagnosis:

  • Enable GC logs: -Xlog:gc*:file=gc.log:time,uptime:filecount=10,filesize=50M
  • Look for: long pause times (p99), full GC frequency, promotion failures, humongous allocations (G1)
  • Heap dumps + allocation profiling (async-profiler, JFR) — kaun allocate kar raha hai?
  • Metrics: pause time distribution, allocation rate (MB/s), live set size

Common causes: high allocation rate (temporary objects, boxing), large live set, humongous objects, insufficient heap, off-heap leak.

JVM Classloader Leaks in Plugin System

Symptoms: Metaspace grows, redeploy ke baad Old Gen mein classes retained, OutOfMemoryError: Metaspace.

Root causes:

  • Static references — plugin class static field se long-lived object reference
  • ThreadLocal — thread pool threads plugin class hold karte hain
  • Threads — plugin ne thread spawn kiya, band nahi hua
  • JDBC drivers / MBeans / shutdown hooks registered, deregister nahi hue
  • Listener registrations — global event bus pe listener chhod diya
  • Parent classloader caches holding plugin objects
🔑 Key Answer

Fixes:

  • Weak references everywhere parent points to plugin
  • Plugin lifecycle — start() / stop() interface, stop must deregister everything
  • Dedicated thread pool per plugin, shutdown on unload
  • Isolate plugins in separate JVMs (strongest, costs resources)
  • Integration test: load plugin → unload → force GC → assert classloader collected
  • OSGi or proper plugin framework with lifecycle guarantees

📊 Custom Collector — {count, total, min, max}

StatsCollector.javaJAVA
record Stats(long count, BigDecimal total,
              BigDecimal min, BigDecimal max) {}

class StatsCollector implements Collector<BigDecimal, StatsAcc, Stats> {

    public Supplier<StatsAcc> supplier() { return StatsAcc::new; }

    public BiConsumer<StatsAcc, BigDecimal> accumulator() {
        return (acc, v) -> {
            acc.count++;
            acc.total = acc.total.add(v);
            if (acc.min == null || v.compareTo(acc.min) < 0) acc.min = v;
            if (acc.max == null || v.compareTo(acc.max) > 0) acc.max = v;
        };
    }

    public BinaryOperator<StatsAcc> combiner() {          // parallel ke liye
        return (a, b) -> {
            a.count += b.count;
            a.total = a.total.add(b.total);
            if (b.min != null && (a.min == null || b.min.compareTo(a.min) < 0)) a.min = b.min;
            if (b.max != null && (a.max == null || b.max.compareTo(a.max) > 0)) a.max = b.max;
            return a;
        };
    }

    public Function<StatsAcc, Stats> finisher() {
        return a -> new Stats(a.count, a.total, a.min, a.max);
    }

    public Set<Characteristics> characteristics() {
        return EnumSet.of(Characteristics.UNORDERED);
    }

    static class StatsAcc {
        long count = 0;
        BigDecimal total = BigDecimal.ZERO, min, max;
    }
}
LineExplanation
Collector<T, A, R>3 type params: T = input, A = accumulator (mutable), R = result.
supplier()Naya accumulator banao. Har partition ke liye alag.
accumulator()Ek element ko accumulator mein add karo. Mutable — fast.
combiner()Parallel ke liye. Do accumulators merge karo. Associative hona chahiye.
finisher()Accumulator → final immutable result.
Characteristics.UNORDEREDOrder matter nahi karta — parallel optimization hint. CONCURRENT hota toh single accumulator.
🔑 Key Answer

Custom collector parallel-safe tab hai jab combiner associative ho. Yahaan min/max/total sab associative hain. UNORDERED characteristic parallel mein speedup deta hai. CONCURRENT + UNORDERED = single shared accumulator (sirf thread-safe accumulator ke saath).

Java parallelStream() — Pitfalls

Pitfalls:

  • Ordering: parallelStream() encounter order guarantee nahi karta unless forEachOrdered ya ordered collector. findFirst vs findAny ka farq.
  • Thread safety: Shared mutable state (ArrayList, HashMap) mein parallel writes → data race. Collectors.toList() safe, manual list.add() nahi.
  • Stateful lambdas: Non-deterministic results.
  • Performance: Common ForkJoinPool use hota hai — blocking I/O poore pool ko starve kar deta.
  • False sharing: Atomic counters pe cache contention.
  • Exceptions: Worker threads mein propagate messy.

Rule of thumb: Parallel tabhi jab data bada (>10k), CPU-bound, side-effect-free, aur benchmark se fayda dikhe.

🔑 Key Answer

Interview mein: "parallelStream by default common ForkJoinPool use karta hai — usse customize karo ya dedicated pool do (custom ForkJoinPool). Blocking I/O ke liye parallelStream bilkul mat use karo. Measurement ke bina parallelize mat karo."

    // each entry: [epochMinute, amountInMinorUnits]

    private static final SecureRandom RNG = new SecureRandom();

    /** 32 bytes = 256 bits of entropy, base64url encoded = ~43 chars. */
    public static String generate() {
        byte[] bytes = new byte[32];
        RNG.nextBytes(bytes);
        return Base64.getUrlEncoder()
                     .withoutPadding()
                     .encodeToString(bytes);
    }

    /** Deterministic key for same logical request (idempotency). */
    public static String deterministic(String clientId,
                                              String requestId,
                                              BigDecimal amount) {
        try {
            MessageDigest md = MessageDigest.getInstance("SHA-256");
            String input = clientId + "|" + requestId + "|" + amount.toPlainString();
            byte[] hash = md.digest(input.getBytes(StandardCharsets.UTF_8));
            return Base64.getUrlEncoder().withoutPadding()
                         .encodeToString(hash).substring(0, 32);
        } catch (NoSuchAlgorithmException e) {
            throw new IllegalStateException(e);
        }
    }
}

public boolean isValidIPv4(String ip) {
    if (ip == null) return false;
    String[] parts = ip.split("\\.", -1);       // -1 keeps trailing empties
    if (parts.length != 4) return false;

    for (String p : parts) {
        if (p.isEmpty() || p.length() > 3) return false;
        if (p.length() > 1 && p.charAt(0) == '0') return false;  // leading zero
        for (char c : p.toCharArray())
            if (!Character.isDigit(c)) return false;
        int v = Integer.parseInt(p);
        if (v < 0 || v > 255) return false;
    }
    return true;
}
