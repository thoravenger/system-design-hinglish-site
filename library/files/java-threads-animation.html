Thread

Ek program, kai workers

Thread program ke andar ek alag worker hai. Sab threads heap (objects) share karte hain, par har thread ka apna stack hota hai. Kaun kab chalega, ye scheduler decide karta hai, isliye har run mein order badal sakta hai.

Ready


  

  
    
    
  • start() naya thread banata hai. run() bas ek normal method call hai, jise main thread hi chalata hai.
    • 
    
  • Ek hi thread pe start() do baar call kiya toh IllegalThreadStateException aayega.
    • 
    
  • Real project mein new Thread() ki jagah ExecutorService (thread pool) use karo.

    2
    
synchronized
Ek time pe sirf ek thread

  

  
count++ ek step nahi, teen steps hai: read, add, write. Do threads beech mein ghus gaye toh ek update gayab ho jaata hai. Isko race condition kehte hain. synchronized object ke built-in lock (monitor) se ek time pe ek hi thread ko andar aane deta hai.

  

    

      

        
        
      

      

      

        
        
        
        
      

      
Ready

    

    

  

  
    
    
  • Method khatam hote hi lock apne aap chhoot jaata hai, exception aaye tab bhi.
    • 
    
  • Lock ka wait karne wala thread BLOCKED state mein hota hai. Thread dump mein yahi dikhega.
    • 
    
  • Sirf ek counter badhana hai? AtomicInteger.incrementAndGet() bina lock ke bhi safe hai.
    • 
  







  

    3
    
ReentrantLock
Chabi aapke haath mein

  

  
Kaam synchronized jaisa hi hai, par control zyada milta hai: tryLock() se wait ki limit, fair queue, aur ek lock pe kai Conditions. Bas unlock() khud karna padta hai, hamesha finally mein.

  

    

      

      

        
        
        
        
      

      
Ready

    

    

  

  
    
    
  • Reentrant ka matlab: jis thread ke paas lock hai, woh dobara bhi le sakta hai. Har baar holdCount +1.
    • 
    
  • Jitni baar lock(), utni baar unlock(). Ek bhi miss hua toh lock hamesha busy rahega aur baaki threads atke rahenge.
    • 
    
  • tryLock(timeout) deadlock se bachne ka sabse aasaan tareeka hai.
    • 
    
  • lock() pe atka thread, thread dump mein WAITING (parking) dikhta hai, BLOCKED nahi.
    • 
  







  

    4
    
CompletableFuture
Wait mat karo, aage ka plan bata do

  

  
Kaam background thread pool ko do, aur pehle se bata do ki result aane par kya karna hai (thenApply, thenCombine…). Main thread free rehta hai. Food delivery app jaisa: order karo, apna kaam karo, khana ready hote hi notification aa jaata hai.

  

    

      

        
        
      

      

      

      

        
        
        
        
      

      
Ready

    

    

  

  
    
    
  • thenApply result badalta hai, thenCombine do results jodta hai, aur thenCompose ek async kaam ke baad doosra async kaam chalata hai.
    • 
    
  • join() aur get() blocking hain. Inhe sirf end mein use karo.
    • 
    
  • Default pool ForkJoinPool.commonPool() hai. DB ya API calls ke liye apna Executor do: supplyAsync(task, executor).
    • 
    
  • exceptionally na ho toh join() CompletionException throw karega.
    • 
  






  
Kab kya use karein?

  

    
synchronized
Shared data ko simple tareeke se safe karna ho

    
ReentrantLock
Timeout, fairness ya multiple Conditions chahiye

    
AtomicInteger
Sirf ek counter ya flag update karna ho

    
CompletableFuture
Kaam background mein chalao, aur result aane par aage ka kaam

    
ExecutorService
Bahut saare tasks ke liye thread pool
