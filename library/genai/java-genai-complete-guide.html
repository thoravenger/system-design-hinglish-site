CHAPTER 1

What is Generative AI?

Generative AI refers to artificial intelligence systems that can generate new content — text, images, code, audio, or video — based on patterns learned from massive amounts of training data. The most important type for Java developers is the Large Language Model (LLM).

1.1 What is a Large Language Model (LLM)?

A Large Language Model is a neural network trained on billions of words of text. It learns statistical patterns between words and can predict what word comes next in a sequence. This simple mechanism — predict the next word — gives rise to an astonishing ability to understand and generate human language. Famous LLMs include OpenAI's GPT-4o, Google's Gemini, Anthropic's Claude, and open-source models like Meta's Llama 3 and Mistral. These models have hundreds of billions of parameters (numerical weights learned during training).

1.2 How Does an LLM Work? (Simple Explanation)

Think of it in three steps:

  • INPUT: You send text (called a prompt) to the model.
  • PROCESSING: The model runs your text through billions of mathematical operations.
  • OUTPUT: The model generates a response, one token at a time.

// LLM API Call

// Calling an LLM is just an HTTP API call POST https://api.openai.com/v1/chat/completions {
"model": "gpt-4o", "messages": [ { "role": "system", "content": "You are a helpful assistant."
}, { "role": "user", "content": "What is Java?" } ] } // Response: { "choices": [{ "message":
{ "role": "assistant", "content": "Java is a high-level, object-oriented programming
    language..." } }] }

Gen AI does NOT replace traditional programming. It adds a layer of language understanding on top of your existing Java applications.

CHAPTER 2

Core Concepts You Must Know

2.1 Tokens — The Currency of LLMs

LLMs do not process text character by character or word by word. They process TOKENS. A token is roughly 4 characters or 0.75 words in English.

// Token Counting

// Token examples: "Hello"   1 token "Hello, how are you?"   5 tokens "Generative AI"   3
tokens "Java Spring Boot"   4 tokens // Rule of thumb: // 1,000 tokens  750 words   1.5 pages
of text // 128,000 tokens  a 100-page book

Tokens matter for three reasons:

  • COST: OpenAI charges per token. More tokens = more money.
  • CONTEXT WINDOW: Each model has a maximum token limit (GPT-4o = 128K tokens).
  • SPEED: More tokens in the prompt = slower response.

2.2 Context Window

The context window is the maximum amount of text (measured in tokens) that an LLM can see at one time. This includes BOTH your input (prompt) AND the model's output (response).

ModelContext WindowApprox. Pages
GPT-3.5-turbo16,000 tokens~12 pages
GPT-4o128,000 tokens~96 pages
Claude 3.5 Sonnet200,000 tokens~150 pages
Llama 3 (8B) via Ollama8,192 tokens~6 pages
Mistral 7B via Ollama32,768 tokens~24 pages

If your document is larger than the context window, you CANNOT just paste it into the prompt. This is exactly why RAG (Chapter 4) was invented.

2.3 Embeddings — Text as Numbers

An embedding is a way of representing text as a list of numbers (a vector). The key insight is that similar text produces similar vectors. This is the mathematical foundation of semantic search and RAG.

// Embedding Concept

"I love Java programming"   [0.23, -0.87, 0.45, 0.12, ...] (1536 numbers) "I enjoy coding in
Java"    [0.22, -0.85, 0.44, 0.11, ...] (very similar!) "I love eating pizza"  [0.91, 0.34,
-0.67, 0.88, ...] (very different) // Similar MEANING   Similar NUMBERS   Close in vector
space // Different MEANING   Different NUMBERS   Far in vector space

2.4 Cosine Similarity

Cosine similarity measures how similar two vectors are. It calculates the angle between them. A score of 1.0 means identical meaning; 0.0 means completely unrelated.

// Cosine Similarity Scale

Cosine Similarity Score Interpretation: 1.0   Identical meaning ("Java" vs "Java") 0.9+
Very similar ("refund policy" vs "return policy") 0.7+   Related ("order status" vs "where is
my package?") 0.5   Somewhat related 0.0   Unrelated ("Java" vs "pizza") -1.0   Opposite
meaning

2.5 Temperature — Controlling Creativity

Temperature is a parameter (0.0 to 2.0) that controls how random or creative the LLM's responses are.

TemperatureBehaviorBest For
0.0Deterministic, always same answerFact extraction, classification, SQL
0.3Consistent, slightly variedQ&A, RAG, customer support
0.7Balanced (default)General chat, summarization
1.0+Creative, unpredictableStory writing, brainstorming

For RAG and factual Q&A;, always use temperature 0.0 to 0.3 to minimize hallucination.

CHAPTER 3

Prompt Engineering

Prompt engineering is the art of writing inputs to LLMs that produce the best outputs. A good prompt can be the difference between a useless response and a perfect one. This is a critical skill for every Java Gen AI developer.

3.1 Types of Prompts

System Prompt

Sets the role, rules, and behavior of the AI. Sent once at the beginning.

// System Prompt Example

// System prompt — tells AI WHO it is and HOW to behave "You are a professional customer
support agent for TechCorp. - Answer ONLY questions related to our products. - Always be
polite and empathetic. - If you cannot help, say: 'Let me connect you to a human agent.' -
Never reveal internal company information. - Always respond in the same language as the
customer." // This shapes EVERY response the AI gives in this session.

User Prompt

The actual question or instruction from the user.

Assistant Prompt

Previous AI responses, included to give context in multi-turn conversations.

3.2 Prompting Techniques

Zero-Shot Prompting

Ask the model to do something without giving any examples.

// Zero-Shot

// Zero-shot: no examples, just ask directly "Classify this customer message as COMPLAINT,
INQUIRY, or COMPLIMENT: Message: 'My order arrived broken and the packaging was terrible!'" //
Model output: COMPLAINT

Few-Shot Prompting

Give 2-3 examples before asking the real question. Much more accurate.

// Few-Shot

// Few-shot: give examples first, then ask "Classify customer messages. Examples: Message:
'Your app is amazing!'   COMPLIMENT Message: 'Where is my order?'   INQUIRY Message: 'This is
broken!'   COMPLAINT Now classify: Message: 'I have been waiting 2 weeks for my delivery.'" //
Model output: COMPLAINT (accurate because of examples!)

Chain-of-Thought Prompting

Tell the model to think step by step. Dramatically improves reasoning.

// Chain-of-Thought

// Add "think step by step" for complex reasoning "A customer ordered 3 items at Rs.500 each.
They used a 10% discount coupon and paid with a credit card that gives 5% cashback. How much
did they actually pay? Think step by step before giving the final answer." // Model thinks: //
Step 1: Total = 3 x 500 = Rs.1500 // Step 2: After 10% discount = 1500 - 150 = Rs.1350 // Step
3: After 5% cashback = 1350 - 67.50 = Rs.1282.50 // Final Answer: Rs.1282.50

CHAPTER 4

RAG — Retrieval Augmented Generation

RAG is the most important Gen AI pattern for enterprise Java developers. It solves the fundamental problem that LLMs do not know your private data, company documents, or recent information. Understanding RAG deeply will make you stand out in any interview.

4.1 The Problem RAG Solves

Without RAG, LLMs have three critical limitations:

  • Knowledge Cutoff: GPT-4o was trained on data up to a certain date. It knows nothing after that.
  • No Private Data: It does not know your company policies, product catalog, or customer orders.
  • Hallucination: When it does not know the answer, it may confidently make one up.

RAG fixes all three by giving the LLM real, relevant information at the time of the query.

4.2 RAG Architecture — The Two Phases

Phase 1: Indexing (Done Once / Offline)

// Indexing Phase

INDEXING PIPELINE: Your Documents (PDF, Word, DB, Website) | v [1] LOAD DOCUMENT | v [2] CHUNK
(split into 500-token pieces with 50-token overlap) | v [3] EMBED each chunk  vector [0.23,
-0.87, 0.45, ...] | v [4] STORE in Vector Database (Pinecone / pgvector / Weaviate) Result:
Your documents are now searchable by MEANING, not keywords.

Phase 2: Querying (Every User Request)

// Query Phase

QUERY PIPELINE: User Question: "What is your refund policy?" | v [1] EMBED the question
vector [0.21, -0.85, 0.44, ...] | v [2] SEARCH Vector DB   find top-3 most similar chunks | v
Retrieved chunks: Chunk 1: "Returns accepted within 30 days..." Chunk 2: "Damaged items
refunded within 60 days..." Chunk 3: "Refunds processed in 5-7 business days..." | v [3] BUILD
PROMPT: System: "Answer ONLY from the context below." Context: [Chunk 1] [Chunk 2] [Chunk 3]
User: "What is your refund policy?" | v [4] LLM generates accurate, grounded answer

4.3 Chunking Strategies

Chunking is splitting large documents into smaller pieces. Bad chunking = bad retrieval = wrong answers. Here are the main strategies:

StrategyHow It WorksBest For
Fixed SizeSplit every N tokens regardless of contentSimple, fast, good baseline
Sentence-basedSplit at sentence boundariesArticles, blogs, paragraphs
RecursiveTry paragraph, then sentence, then wordMixed content (recommended)
Sliding WindowChunks overlap by N tokensPrevents losing context at boundaries
SemanticGroup by topic/meaningComplex, technical documents

Use recursive chunking with 500 tokens and 50-token overlap as your default. This works well for 90% of use cases.

4.4 Full RAG Code with LangChain4j

// Complete RAG Implementation

@Service public class RagService { private final EmbeddingModel embeddingModel; private final
    EmbeddingStore&lt;TextSegment&gt; embeddingStore; private final ChatLanguageModel llm; // STEP
    1: INDEX a document (call once per document) public void indexDocument(String filePath) {
        Document doc = FileSystemDocumentLoader.loadDocument(filePath); // Chunk: 500 tokens, 50
        overlap DocumentSplitter splitter = DocumentSplitters.recursive(500, 50);
        EmbeddingStoreIngestor.builder() .documentSplitter(splitter) .embeddingModel(embeddingModel)
        .embeddingStore(embeddingStore) .build() .ingest(doc); System.out.println("Document
        indexed!"); } // STEP 2: QUERY (call on every user question) public String ask(String
    question, String sessionId) { // Set up retriever: search vector DB
        EmbeddingStoreContentRetriever retriever = EmbeddingStoreContentRetriever.builder()
        .embeddingStore(embeddingStore) .embeddingModel(embeddingModel) .maxResults(3) // top 3 chunks
        .minScore(0.7) // only relevant chunks .build(); // Build RAG-powered agent RagAgent agent =
        AiServices.builder(RagAgent.class) .chatLanguageModel(llm) .contentRetriever(retriever) // RAG
        enabled! .chatMemory(MessageWindowChatMemory.withMaxMessages(10)) .build(); return
        agent.chat(question); } } // Agent interface interface RagAgent { @SystemMessage(""" Answer
ONLY from the provided context. If not found, say: 'I could not find that in our documents.'
""") String chat(String question); }

4.5 RAG vs Fine-Tuning — When to Use Which

AspectRAGFine-Tuning
What it doesInjects knowledge at runtimeBakes knowledge into model weights
CostLow (vector DB + API calls)Very high ($500 to $100,000+)
Update dataInstant (re-index)Retrain model (days/weeks)
Best forDynamic, private, recent dataChanging behavior/style/tone
Hallucination riskLow (grounded in context)Medium (model may still hallucinate)
Java complexityModerateRequires Python/ML knowledge

Rule of thumb: Use RAG for KNOWLEDGE problems. Use Fine-tuning for BEHAVIOR problems. Most enterprise apps only ever need RAG.

CHAPTER 6

AI Agents and Tool Calling

A regular LLM answers questions from its training. An AI agent can TAKE ACTIONS — query your database, call external APIs, send emails, calculate values, and more. This is what makes Gen AI truly powerful for enterprise applications.

6.1 What is an AI Agent?

// Agent vs LLM

REGULAR LLM: User   LLM    Answer (can only use training data, may hallucinate) AI AGENT: User
   LLM   "I need real data"   Call Tool    Get Result   LLM    Answer (uses REAL data from
YOUR systems, no hallucination on facts) Example: User: "What is the status of order
ORD-12345?" Without agent: LLM guesses or says "I don't know"  With agent: LLM thinks: "I
need to look up this order" LLM calls: getOrderById("ORD-12345") DB returns: {status:
"SHIPPED", expectedDelivery: "Jan 25"} LLM responds: "Your order ORD-12345 is shipped,
arriving Jan 25."

6.2 The ReAct Pattern

ReAct (Reason + Act) is the most popular agent pattern. The LLM alternates between thinking (reasoning) and acting (calling tools) until it has a complete answer.

// ReAct Loop

User: "What is the weather in Mumbai and how does it compare to Delhi?" [THOUGHT] I need to get
weather data for both cities. [ACTION] call getWeather("Mumbai") [RESULT] "Mumbai: 32 deg C,
humidity 85%" [THOUGHT] Now I need Delhi's weather. [ACTION] call getWeather("Delhi") [RESULT]
"Delhi: 38 deg C, humidity 45%" [THOUGHT] I have both. I can now compare and answer. [ANSWER]
"Mumbai is 32 deg C with high humidity. Delhi is hotter at 38 deg C but less humid. Delhi is 6
degrees warmer today."

6.3 Building Tools in Java

// Tool Definition

// Tools are just regular Java methods with @Tool annotation // The description tells the LLM
WHEN to call this tool @Component public class OrderTool { @Autowired private OrderRepository
    orderRepo; // LLM reads this description to decide when to call this method @Tool("Get order
    details by order ID. " + "Call this when the customer provides an order number.") public
    String getOrderById(String orderId) { return orderRepo.findById(orderId) .map(o -> "Order: " +
        o.getId() + ", Status: " + o.getStatus() + ", Total: Rs." + o.getTotal()) .orElse("Order not
        found: " + orderId); } @Tool("Get all orders for a customer. " + "Call this when customer
        provides their email address.") public String getOrdersByEmail(String email) {
            List&lt;Order&gt; orders = orderRepo.findByEmail(email); if (orders.isEmpty()) return "No
            orders found for: " + email; return orders.stream() .map(Order::toString)
            .collect(Collectors.joining(", ")); } @Tool("Calculate refund amount for an order.") public
        String calculateRefund(String orderId, double percentage) { return orderRepo.findById(orderId)
            .map(o -> "Refund: Rs." + (o.getTotal() * percentage / 100)) .orElse("Order not found"); } }

CHAPTER 7

Vector Databases

A vector database is a specialized database for storing and searching embeddings (vectors). It is the backbone of RAG. Without a vector database, you cannot do semantic search at scale.

7.1 Why Not Use a Regular Database?

// SQL vs Vector DB

// Regular SQL - exact keyword match only: SELECT * FROM docs WHERE content LIKE '%refund%' //
Misses: "money back", "return policy", "reimbursement" // Vector DB - semantic search: "What
is your money-back guarantee?" // Finds: refund policy, return terms, reimbursement policy //
   Understands MEANING, not just keywords

7.3 Using pgvector (PostgreSQL)

If your app already uses PostgreSQL, pgvector is the easiest choice. No new infrastructure needed.

// pgvector SQL

-- 1. Enable the vector extension CREATE EXTENSION IF NOT EXISTS vector; -- 2. Create table
with vector column CREATE TABLE document_chunks ( id SERIAL PRIMARY KEY, content TEXT NOT
NULL, source VARCHAR(255), embedding vector(1536) -- 1536 for OpenAI embeddings ); -- 3.
Create index for fast similarity search CREATE INDEX ON document_chunks USING ivfflat
(embedding vector_cosine_ops); -- 4. Similarity search query SELECT content, 1 - (embedding
&lt;=&gt; '[0.1,0.2,...]') AS score FROM document_chunks ORDER BY embedding &lt;=&gt;

This is the most important strategic chapter. Using AI where it does not belong is expensive, slow, and unreliable. Using it where it shines creates incredible value. Know the difference.

9.1 USE Gen AI When...

9.2 DO NOT Use Gen AI When...

  • PRECISE CALCULATIONS: Use a calculator, not an LLM. LLMs can make arithmetic errors.
  • REAL-TIME DATA: LLMs have no live data. Use APIs + Agent tools for that.
  • SIMPLE CRUD: Creating, reading, updating, deleting records. Just use JPA/SQL.
  • GUARANTEED ACCURACY: Medical dosing, financial transactions, legal contracts — too high stakes for

LLMs alone.

  • HIGH VOLUME SIMPLE TASKS: If a simple regex or SQL query does it, don't pay per LLM token.
  • SECURITY-CRITICAL DECISIONS: Never let an LLM decide who gets access to what.

CHAPTER 12

Interview Preparation — 50 Q&A;

These are the most commonly asked questions in Java + Gen AI interviews, grouped by topic. Study them in order. The answers here are written as you should say them in an interview — clear, confident, and to the point.

Conceptual Questions

Q: What is RAG and why is it used?

A: RAG stands for Retrieval Augmented Generation. It solves the problem that LLMs don't know private or recent data. We index documents as vectors in a vector DB. At query time, we embed the user's question, find the most similar document chunks, and include them in the LLM prompt as context. The LLM then answers based on that real context instead of guessing.

Q: What is an embedding?

A: An embedding is a numerical vector representation of text. An embedding model converts text into a list of numbers (typically 1536 numbers for OpenAI). Similar text produces similar vectors. This allows us to do mathematical similarity search — finding chunks of text that are semantically related to a user's question.

Q: What is cosine similarity?

A: Cosine similarity measures the angle between two vectors. A score of 1.0 means identical meaning, 0.7+ means very similar, and 0.0 means unrelated. Vector databases use cosine similarity to find the most relevant document chunks for a given query.

Q: What is chunking and why does overlap matter?

A: Chunking splits large documents into smaller pieces that fit within the LLM context window. Overlap (typically 50 tokens) between chunks prevents losing important context that might fall at a chunk boundary. Without overlap, a sentence that spans two chunks might be split in a way that loses its meaning.

Q: What is hallucination and how do you prevent it?

A: Hallucination is when an LLM generates confident but false information not grounded in facts. Prevention: use RAG to provide real context, set a minimum similarity score so only relevant chunks are used, instruct the LLM to say 'I don't know' if the answer is not in the context, and include source citations so users can verify.

Q: What is a context window?

A: The context window is the maximum number of tokens an LLM can process in a single request — including both the input prompt and the output. GPT-4o has a 128K token context window. This is why we use chunking and RAG instead of pasting entire documents into the prompt.

Q: What is the difference between RAG and fine-tuning?

A: RAG retrieves external knowledge at runtime — it's cheap, updatable without retraining, and good for dynamic private data. Fine-tuning bakes knowledge into model weights during training — it's expensive, static, and best for changing the model's behavior or style. Most enterprise applications only need RAG.

Q: What is function/tool calling?

A: Tool calling allows the LLM to call predefined Java methods to get real data. The LLM reads the @Tool description and decides when to call each method. For example, when a user asks about an order, the LLM calls getOrderById(), gets the real DB result, and uses that to form the answer. This eliminates hallucination for structured data.

Q: What is the ReAct agent pattern?

A: ReAct stands for Reason and Act. The agent alternates between thinking about what it needs (Reason) and calling a tool to get it (Act), repeating until it has enough information to answer the user's question. It is the

most popular pattern for building AI agents.

Q: What is a vector database?

A: A vector database is specialized for storing and searching high-dimensional vectors (embeddings). Unlike SQL that matches exact values, a vector DB finds vectors that are mathematically close — enabling semantic similarity search. Examples: Pinecone, pgvector, Weaviate, Qdrant.

Technical Implementation Questions

Q: How do you implement streaming responses?

A: Use StreamingChatLanguageModel instead of ChatLanguageModel. The response comes back as a Flux<String> using Project Reactor. On the controller side, return Flux<String> with MediaType.TEXT_EVENT_STREAM_VALUE so the client receives tokens as they are generated, just like ChatGPT.

Q: How do you manage per-user conversation memory?

A: Use a ConcurrentHashMap<String, ChatMemory> keyed by sessionId. Each user gets their own MessageWindowChatMemory. In production, replace this with Redis and set a TTL (e.g., 1 hour) so sessions are automatically cleaned up.

Q: How do you handle OpenAI rate limits?

A: Use Spring's @Retryable annotation with exponential backoff — retry up to 3 times, doubling the wait each time (1s, 2s, 4s). Add a @Recover method that returns a fallback message if all retries fail. For bulk tasks, use the OpenAI Batch API which is 50% cheaper and not rate-limited.

Q: How do you secure an LLM application?

A: Store API keys in environment variables, never in code. Rate-limit per user using Bucket4j. Validate and sanitize user input to prevent prompt injection. Scan LLM outputs before sending to users. Log all LLM calls for audit. Use separate API keys per environment.

Q: How do you evaluate RAG quality?

A: Use four metrics: Faithfulness (is the answer grounded in the retrieved context?), Answer Relevance (does the answer actually address the question?), Context Recall (were the right chunks retrieved?), and Context Precision (were all retrieved chunks relevant?). The RAGAs framework automates these measurements.

Q: What is minScore and why is it important?

A: minScore is a threshold on the cosine similarity score. Only chunks with a score above this threshold are included as context. This prevents irrelevant chunks from being injected into the prompt, which would confuse the LLM. A good starting value is 0.6-0.7. Without minScore, even very irrelevant chunks get sent to the LLM.

Q: How do you implement multi-tenant RAG?

A: Use namespaces in your vector DB — one namespace per tenant. During indexing, store chunks in the tenant's namespace. During retrieval, filter by tenantId so each tenant only sees their own data. Pinecone and Weaviate both support namespaces natively.

Q: How do you handle documents larger than the context window?

A: This is exactly what RAG solves. Index the entire document in chunks. At query time, only retrieve the 3-5 most relevant chunks. The LLM never sees the whole document — only the parts relevant to the current question. For very large documents, also use parent-child chunking for better precision.

System Design Questions

Q: Design a RAG system for 10 million documents.

A: Use Kafka for async ingestion: documents flow through a queue to worker pods that chunk, embed, and store in Pinecone. For querying: API Gateway → Auth → Rate Limit → Query Service (embed query →

Pinecone search → rerank → LLM call) → Redis cache for frequent queries. Scale horizontally with Kubernetes.

Q: How would you reduce LLM costs in production?

A: Five strategies: 1) Cache responses in Redis — same questions get cached answers with no LLM call (30-50% savings). 2) Route simple tasks to cheaper models (GPT-3.5 for classification, GPT-4 for complex reasoning). 3) Optimize prompts — shorter prompts cost less. 4) Use batch API for non-urgent processing (50% cheaper). 5) Use local Ollama for development and non-critical features.

Q: How do you ensure LLM output quality in production?

A: Use LLM-as-judge pattern: after generating a response, a second LLM call evaluates it for accuracy, relevance, and hallucination. Log all responses. Collect user feedback (thumbs up/down). A/B test different prompts. Monitor RAGAs metrics continuously. Set up alerts when quality scores drop below threshold.

Glossary, Resources & Next Steps

Glossary — Every Term Explained

Agent: An LLM combined with tools, memory, and a loop that lets it take real actions.

Chunking: Splitting documents into smaller pieces (typically 500 tokens) for embedding.

Context Window: Maximum tokens an LLM can process in one request (input + output).

Cosine Similarity: Mathematical measure of angle between two vectors. 1.0 = identical, 0.0 = unrelated.

Embedding: A vector (list of numbers) representation of text. Similar text = similar vectors.

Fine-tuning: Training a pre-existing model on custom data to change its behavior or style.

Hallucination: LLM generating confident but false information.

LangChain4j: Java framework for building AI applications with agents, RAG, and memory.

LLM: Large Language Model. AI trained on massive text data to understand and generate language.

Namespace: Isolation unit in vector DBs. Used for multi-tenant RAG.

Ollama: Tool for running open-source LLMs locally, for free.

Prompt: The text input you send to an LLM.

RAG: Retrieval Augmented Generation. Fetching relevant document chunks and injecting into prompt.

ReAct: Reason + Act. Agent pattern where LLM alternates between thinking and calling tools.

System Prompt: Instructions that define the AI's role and behavior for an entire conversation.

Temperature: 0.0-2.0 parameter controlling randomness. 0.0 = deterministic, 1.0+ = creative.

Token: Basic unit of LLM text processing. ~4 characters or 0.75 words.

Tool Calling: LLM ability to call predefined Java methods to get real data.

Vector Database: Database optimized for storing and searching embeddings by similarity.
