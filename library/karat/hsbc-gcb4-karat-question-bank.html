How the HSBC Karat round works

For HSBC Java backend roles, expect a 60-minute live, recorded Karat interview: quick system-design answers first, then fixing and extending an existing backend codebase against failing tests. Karat’s standard split is a brief intro, 10 minutes of discussion and 40 minutes of programming (Karat candidate guide). HSBC backend invites name the two sections "Discussion and Analysis Questions: System Design" and "Live Coding: Develop and Update Backend Code" (Glassdoor, HSBC-India).

SegmentTimeWhat happens
Intro~5 minInterviewer explains the format; you give a short self-introduction
Discussion and analysis (system design)10–20 min4–5 scenario questions, each answered in 1–2 lines
Live coding, part 1: debug~20 minRead the given code, run the failing unit tests, fix the code until they pass
Live coding, part 2: enhanceRest of the hourAdd a new requirement to the same code and keep every test green

Times for the two coding parts are approximate; candidates describe a 20-minute design block, then a fix-then-enhance task on one codebase.

How you are scored. The rubric covers coding, testing, defect management and troubleshooting, ending in Do Not Recommend, Recommend or Strongly Recommend (Karat Studio guide). Karat says its top criterion is how successfully your code solves the problem. HSBC’s recruiter gets the recording plus a written summary and decides the next step.

The IDE (Karat Studio). Java has autocomplete, a built-in test runner and a whiteboard for design sketches. You see one question at a time, with its prompt, starter code and test cases. Set key bindings (VS Code, Vim or Emacs), theme and font size before the clock starts.

Variants to be ready for

  • Classic algorithmic format: two multi-part coding problems (see Coding problems), still common with other Karat clients.
  • Code review: review a snippet, name the issues and explain the fixes, then a debug-until-tests-pass task (Glassdoor, HSBC Karat Studio).
  • NextGen (AI-enabled): a VS Code-based IDE with a built-in AI assistant you are expected to use; outside AI tools are banned (Karat NextGen).

What GCB-4 adds. GCB-4 is HSBC’s senior/lead career band (Glassdoor GCB4 listing). An inference, not a published rule: at this band, design answers must name trade-offs and failure modes, and both coding parts should finish with all tests green.

Core Java quick-fire

These 31 questions cover the Java topics HSBC interviewers keep returning to (Glassdoor, HSBC Senior Java Developer; GeeksforGeeks, HSBC SDE-2). HSBC’s Karat discussion block leans on design, so these mostly feed your design answers and HSBC’s own technical round after Karat. Answer in one or two sentences, then give one example from your project.

Collections and core language

HashMap vs ConcurrentHashMap? HSBC
HashMap is unsynchronized and allows one null key. ConcurrentHashMap gives lock-free reads, per-bin CAS/locking on writes, no null keys or values, and weakly consistent iterators.
How does HashMap work internally?
Buckets indexed by the spread hash; collisions chain in a list that becomes a red-black tree past 8 entries (table ≥ 64). It doubles capacity when size exceeds capacity × 0.75.
Why override equals() and hashCode() together?
Equal objects must share a hash code, or hash-based collections put them in different buckets and lookups fail.
Comparable vs Comparator? HSBC
Comparable is the class’s single natural order (compareTo). Comparator is an external, swappable order, composable with Comparator.comparing(...).thenComparing(...).
What makes a class immutable? HSBC
Final class, private final fields, no setters, defensive copies of mutable inputs and outputs. Records and String are examples, and immutables are thread-safe by design.
Why is String immutable? String vs StringBuilder vs StringBuffer?
Immutability enables the string pool, cached hash codes and safe sharing. StringBuilder is mutable and unsynchronized; StringBuffer is the synchronized, slower variant.
ArrayList vs LinkedList?
ArrayList has O(1) index access and cache-friendly iteration. LinkedList only wins for insert/remove at an already-held node, so ArrayList is the default.
Fail-fast vs fail-safe iterators?
Fail-fast iterators (ArrayList, HashMap) throw ConcurrentModificationException on structural change. CopyOnWriteArrayList iterates a snapshot; ConcurrentHashMap tolerates concurrent change.
When do you pick LinkedHashMap or TreeMap? HSBC
LinkedHashMap keeps insertion or access order, so it makes an LRU cache via removeEldestEntry. TreeMap keeps keys sorted, O(log n), with floor/ceiling range queries.
Checked vs unchecked exceptions?
Checked exceptions must be declared or handled; unchecked ones extend RuntimeException. Spring’s @Transactional rolls back on unchecked exceptions by default, not checked ones.

Java 8+ and functional style

What is a functional interface? Predicate vs Function vs Supplier vs Consumer? HSBC
One abstract method, so a lambda can implement it. Predicate tests (T → boolean), Function maps (T → R), Supplier produces, Consumer consumes; BiPredicate takes two arguments.
Intermediate vs terminal stream operations: why are streams lazy? HSBC
map, filter and sorted only build the pipeline; nothing runs until collect, reduce or forEach. Laziness enables short-circuiting with findFirst or limit.
map vs flatMap?
map transforms one element into one element. flatMap turns each element into a stream and flattens, e.g. List<List<T>> into List<T>.
When should you avoid parallel streams?
Small data, blocking I/O, shared mutable state or order-sensitive work. They share the common ForkJoinPool, so one slow task can starve the whole app.
Optional best practices? HSBC
Use it only as a return type for "may be absent". Prefer map, orElseGet and orElseThrow; never use it for fields or parameters, and never call get() unchecked.
Sum amounts per account in one statement?
txns.stream().collect(groupingBy(Txn::account, reducing(BigDecimal.ZERO, Txn::amount, BigDecimal::add))). Say why money uses BigDecimal, never double.
Records, sealed classes, virtual threads: which have you used?
Records (Java 16) are immutable data carriers; sealed classes (17) restrict subtypes; virtual threads (21) make blocking, thread-per-request code cheap.

Concurrency

synchronized vs ReentrantLock? HSBC
Both give reentrant mutual exclusion. ReentrantLock adds tryLock with timeout, interruptible waits, fairness and multiple Conditions, but you must unlock in finally.
volatile vs AtomicInteger?
volatile gives visibility and ordering, not atomicity, so count++ still races. AtomicInteger does atomic read-modify-write with CAS.
How do you size and configure a thread pool? HSBC
CPU-bound work: about the core count; I/O-bound: cores × (1 + wait/compute time). Build ThreadPoolExecutor with a bounded queue and a rejection policy; Executors.newFixedThreadPool hides an unbounded queue.
CountDownLatch vs CyclicBarrier vs Semaphore? HSBC
Latch: one-shot wait until N events happen. Barrier: N threads wait for each other and it resets. Semaphore: caps concurrent access at N permits.
wait/notify vs BlockingQueue? HSBC
wait/notify must run inside synchronized code and re-check the condition in a while loop. BlockingQueue put/take gives producer-consumer without hand-rolled signaling.
What is ThreadLocal, and its risk in thread pools? HSBC
A per-thread variable, such as request context. Pooled threads keep old values, so call remove() in finally or you leak memory and data between requests.
CompletableFuture: thenApply vs thenCompose? How do you fan out and join?
thenApply maps a result; thenCompose chains another async call. Fan out with supplyAsync on your own executor, then allOf(...).join().
What causes deadlock, and how do you prevent it?
Threads holding locks while waiting for each other in a cycle. Prevent with a global lock order, tryLock timeouts or smaller lock scopes; confirm with a thread dump (jstack).

JVM and memory

Heap vs stack: what lives in Metaspace?
Each thread’s stack holds frames, primitives and references; the heap holds objects in young and old generations. Metaspace holds class metadata in native memory.
How does G1 work, and what do you use for low latency?
G1 (default since Java 9) splits the heap into regions and collects the most-garbage regions first against a pause target. ZGC or Shenandoah keep pauses in low milliseconds on large heaps.
How do you diagnose a memory leak in production?
Watch old-gen usage after each full GC, capture a heap dump (-XX:+HeapDumpOnOutOfMemoryError or jmap), and read the dominator tree in Eclipse MAT. Usual suspects: static caches, listeners, ThreadLocals.
Strong vs soft vs weak references?
Strong: never collected while reachable. Soft: cleared under memory pressure, useful for caches. Weak: cleared at the next GC, as with WeakHashMap keys.

Design principles

SOLID with one example each? HSBC
S: a PaymentValidator only validates. O: add a payment type as a new strategy class. L: subtypes keep the base contract. I: small role interfaces. D: services depend on interfaces Spring injects.
Which design patterns have you used in Spring apps? HSBC
Singleton beans, Factory (BeanFactory), Proxy (AOP and @Transactional), Template Method (JdbcTemplate), Strategy (payment routing), Builder, and Observer (ApplicationEvent).

Spring and Spring Boot quick-fire

HSBC candidates report Spring Security, bean basics, the purpose of DTOs, API performance and data-security measures (Glassdoor, HSBC Senior Software Engineer; Glassdoor, HSBC Senior Java Developer). These 28 add the transaction and testing traps that separate a lead from a senior developer.

Core container

IoC and DI: constructor or field injection?
The container creates and wires beans. Prefer constructor injection: final dependencies, fails fast at startup, and unit-testable without Spring.
Bean scopes and lifecycle? HSBC
Scopes: singleton (default), prototype, request, session. Lifecycle: instantiate, inject, BeanPostProcessor before-init, @PostConstruct, BeanPostProcessor after-init (proxies are created here), use, @PreDestroy.
You inject a prototype bean into a singleton. What goes wrong?
It is injected once, so the singleton reuses one instance. Use ObjectProvider<T>, @Lookup or a scoped proxy.
Two beans of the same type: how does Spring choose?
Mark a default with @Primary, pick with @Qualifier, or inject List<T> or Map<String, T> for strategy selection.
@Component vs @Service vs @Repository vs @Controller?
All are scan stereotypes. @Repository also translates persistence exceptions into DataAccessException; @RestController adds @ResponseBody.
How do you fix a circular dependency?
Redesign: extract a third bean or use events. Spring Boot 2.6+ rejects circular references by default; @Lazy on one side is only a stopgap.

Spring Boot

How does auto-configuration work?
@EnableAutoConfiguration loads candidates from AutoConfiguration.imports and applies them through conditions such as @ConditionalOnClass and @ConditionalOnMissingBean. Run with --debug to see the conditions report.
Externalized config and profiles?
Command-line args override environment variables, which override application-{profile}.yml, which overrides application.yml. Bind with @ConfigurationProperties; keep secrets in a vault, never in Git.
What does Actuator give you in production?
Health with liveness/readiness groups, Micrometer metrics for Prometheus, info, and /loggers to change log levels live. Restrict which endpoints are exposed.
What are starters?
Curated dependency bundles such as spring-boot-starter-web, with versions managed by the Boot BOM.

Web and REST

What happens to a request in Spring MVC?
DispatcherServlet, HandlerMapping, your controller, then an HttpMessageConverter (Jackson) writes the response.
How do you handle errors globally?
@RestControllerAdvice with @ExceptionHandler methods returning ProblemDetail (RFC 9457) and correct status codes; never leak stack traces.
How do you validate input?
@Valid on the @RequestBody plus Bean Validation (@NotNull, @Size, @Pattern). Map MethodArgumentNotValidException to a 400 with field errors.
Why use DTOs instead of exposing entities? HSBC
They decouple the API contract from the schema, stop lazy-loading surprises and accidental PII exposure, and allow versioning. Map with MapStruct.
Which HTTP methods are idempotent, and how do you make POST safe to retry?
GET, PUT and DELETE are idempotent; POST is not. Accept an Idempotency-Key header, store key and result, and replay the stored result on retries. This is essential for payments.
Fine-grained vs coarse-grained APIs? HSBC
Fine-grained means many small, chatty calls; coarse-grained means fewer business-level operations. Prefer coarse-grained at service boundaries, documented with OpenAPI.
How do you improve API performance? HSBC
Measure p95/p99 first. Then paginate, cache (Caffeine or Redis, ETags), kill N+1 queries, go async for slow downstreams, tune connection pools and compress responses.
How do you version APIs?
URI (/v2/...), header or media type. Run old versions until consumers migrate, with published deprecation dates.

Transactions

How does @Transactional work, and why does self-invocation break it?
Spring wraps the bean in a proxy that begins and commits the transaction. A call from inside the same class skips the proxy; move the method to another bean or use TransactionTemplate.
Propagation REQUIRED vs REQUIRES_NEW?
REQUIRED joins the current transaction or starts one. REQUIRES_NEW suspends it and commits independently, which suits audit logs that must survive an outer rollback.
Isolation levels and the anomalies they stop?
READ_COMMITTED stops dirty reads, REPEATABLE_READ stops non-repeatable reads, SERIALIZABLE stops phantoms. Most systems run READ_COMMITTED plus row locking on hot rows.
Why didn’t my checked exception roll back?
Default rollback covers RuntimeException and Error only. Add rollbackFor = Exception.class or throw an unchecked exception.

Security

How does the Spring Security filter chain authenticate a request? HSBC
Filters run before DispatcherServlet: a filter extracts the credential or token, the AuthenticationManager verifies it, and the result lands in SecurityContextHolder. Authorize with requestMatchers or @PreAuthorize.
How do you secure microservice APIs with OAuth2/JWT?
Each service is a resource server that checks the JWT signature (JWKS), issuer, audience and expiry. Map scopes to authorities, keep tokens short-lived, and add mTLS between services.
When can you disable CSRF protection?
Keep it for cookie or session auth in browsers. Stateless APIs that take bearer tokens in headers can disable it.
What measures have you taken to ensure system and data security? HSBC, 2026
Be specific: OWASP Top 10 checks, input validation, vault-held secrets, TLS in transit, encryption at rest, PII masking in logs, dependency scanning, least-privilege access and audit trails.

Testing

@SpringBootTest vs @WebMvcTest vs @DataJpaTest?
Full context vs web slice (MockMvc with @MockitoBean services) vs JPA slice. Slices start faster and fail closer to the bug.
How do you test against real infrastructure?
Testcontainers for Postgres or Kafka, WireMock for downstream HTTP, and contract tests (Pact or Spring Cloud Contract) between services.

Karat design block: scenarios and microservices quick-fire

HSBC’s design block is 4–5 scenario questions, each answered in one or two lines, so practise naming the problem and the fix in under 20 seconds. Use the pattern Problem → Fix → Trade-off. Karat rotates its questions, so treat the reported ones below as patterns, not a leak.

Scenarios Karat candidates have reported

Sources: LeetCode, Karat assessment; LeetCode, System Design Karat questions.

Vending machines worldwide all sync at 1 AM every night. Any problem?
One global time means a thundering herd on the server, and every machine runs up to 24 hours on stale prices and stock. Stagger with jitter, sync incrementally or on events, retry with backoff.
How would you estimate capacity for an in-house photo store?
Users × photos per day × average size × replicas × retention, plus thumbnails and ~30% headroom. Example: 1M users × 2 photos × 3 MB × 3 replicas ≈ 18 TB/day, about 6.5 PB/year.
Photos are stored on servers chosen by the username’s first letter. Any problem?
Skew: far more names start with S or A than X, so some servers run hot and resharding is painful. Use hash-based sharding with consistent hashing.
Move analysis takes 1 minute per move on a powerful computer, ~200 moves a game: phone or server farm?
Phone: works offline and costs nothing to run, but is slow, drains battery and varies by device. Servers: fast and consistent but cost scales with users and needs a queue; a hybrid splits quick and deep analysis.
A Google-Docs-style app uses a round-robin load balancer. Any issue?
Editors of one document land on different servers, so live sessions and in-memory state split and edits conflict. Route by document ID (consistent hashing) or share state through pub/sub with OT/CRDT merging.
Strong or eventual consistency for (a) bank deposits and payments, (b) streaming metadata, (c) viewer-count analytics?
(a) strong; (b) eventual with caching; (c) eventual. Say why: money needs correctness, the others trade freshness for speed.
Only successful document notifications are logged; failures leave no trace. How do you find every failure across millions of documents?
Set difference: signed document IDs minus logged-sent IDs, as a partitioned batch anti-join. Going forward, add an outbox with status, retries and a dead-letter queue.
A friendship is stored once in either direction (A,B or B,A). How do you count a user’s friends at scale?
Two indexed lookups (user1 = X, user2 = X) combined with UNION ALL. At scale, write both directions or keep a denormalized friend_count updated by events.
Nodes with different capacities form a graph. What is the system’s throughput?
The max flow from source to sink; the minimum cut is the bottleneck, not simply the slowest single node.

Banking-flavoured variants to rehearse

These are extrapolated from the reported patterns above, not reported questions.

Several users update the same record at once. What breaks?
Lost updates. Use optimistic locking (version column, retry on conflict) or row locks for hot records.
A payment call times out and the client retries. Risk?
Double debit. Require an idempotency key backed by a unique constraint, and return the original result on retry.
The nightly interest batch for 50M accounts overruns into business hours. Ideas?
Partition by account range and run in parallel, process only changed accounts, checkpoint and restart (Spring Batch), and read from a replica.
Your service calls a slow credit-bureau API and threads pile up. Fix?
Tight timeouts, a circuit breaker, a separate bulkhead pool, and async processing with a callback where the journey allows.
Account balances are cached in Redis for speed. Risk?
Debits approved against a stale balance. Never authorize from cache; check the balance inside the database transaction.
Logs contain full card numbers. Problem?
A PCI DSS breach. Mask to the last four digits, tokenize, restrict log access and purge old logs.

Microservices, messaging and cloud quick-fire

How should services that own different databases talk to each other? HSBC
Database per service: synchronous REST or gRPC when you need an answer now, Kafka events for state changes. Never share tables; keep data consistent with sagas and the outbox pattern.
Saga: choreography or orchestration?
Choreography: services react to each other’s events, simple but the flow is implicit. Orchestration: a coordinator issues commands and compensations, explicit and easier to monitor, which is better for multi-step payments.
What is the transactional outbox, and why use it?
Save the state change and its event in one local transaction; a relay (Debezium CDC or a poller) publishes to Kafka. It removes dual-write inconsistency.
Circuit breaker states?
Closed (calls pass, failures counted), Open (fail fast to a fallback), Half-open (trial calls decide). Pair Resilience4j with timeouts, bulkheads and backoff retries.
Why can retries make an outage worse?
Retry storms multiply load on a struggling service. Cap attempts, add exponential backoff with jitter, and retry only idempotent calls.
How does Kafka guarantee ordering?
Only within a partition. Key messages by account ID so one account’s events stay in order.
Delivery semantics: how do you handle duplicates?
At-least-once is the norm, so make consumers idempotent by deduplicating on event ID. Exactly-once needs an idempotent, transactional producer and read_committed consumers, and holds only inside Kafka.
Consumer groups, rebalancing and lag?
Partitions split across group members; extra consumers beyond the partition count sit idle. Exceeding max.poll.interval.ms triggers a rebalance, so watch lag.
How do you handle a poison message?
Retry a few times, then park it on a dead-letter topic with error details, alert, and replay after the fix.
What belongs in an API gateway?
Routing, token validation, rate limiting, TLS termination and light aggregation. Keep business logic out.
How do you trace one request across services?
Propagate a W3C trace ID with Micrometer Tracing or OpenTelemetry, export to Jaeger, Zipkin or Tempo, and print trace IDs in structured logs.
Liveness vs readiness vs startup probes? HSBC
Liveness restarts a stuck container. Readiness removes it from traffic until it can serve. Startup holds the other two off during a slow boot.
How do you fix an OutOfMemoryError in a container? HSBC
Identify the kind: heap, Metaspace, direct memory or native threads. Size the heap with -XX:MaxRAMPercentage under the container limit, analyse a heap dump, then fix the leak or bound caches and queues.
How do you deploy with zero downtime?
Rolling or blue-green/canary releases gated by readiness probes, backward-compatible expand-and-contract DB migrations (Flyway or Liquibase), and feature flags.
Which rate-limiting algorithm would you use?
Token bucket allows bursts, leaky bucket smooths traffic, sliding window is most accurate. Enforce at the gateway with a shared Redis counter.
CAP for a banking ledger?
During a partition choose consistency: reject or queue writes rather than risk a double spend. Serve read-only views with a staleness warning if needed.

SQL, JPA and data quick-fire

HSBC candidates report database questions and SQL-vs-NoSQL choices next to the Java topics (Glassdoor, HSBC Senior Java Developer; GeeksforGeeks, HSBC SDE-2). Be ready to write one query by hand and to explain one JPA performance fix.

SQL

Second-highest salary per department?
SELECT dept, salary FROM (SELECT dept, salary, DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) r FROM emp) t WHERE r = 2; DENSE_RANK handles ties.
Find duplicate transactions (same account, amount and timestamp)?
SELECT account_id, amount, txn_ts, COUNT(*) FROM txn GROUP BY account_id, amount, txn_ts HAVING COUNT(*) > 1;
Running balance per account?
SUM(amount) OVER (PARTITION BY account_id ORDER BY txn_ts ROWS UNBOUNDED PRECEDING).
Accounts with no transactions in 90 days?
Use NOT EXISTS against the date-filtered transactions. NOT IN breaks silently if the subquery returns a NULL.
WHERE vs HAVING; INNER vs LEFT JOIN?
WHERE filters rows before grouping, HAVING filters groups. LEFT JOIN keeps unmatched left rows with NULLs.
How does a B-tree index help, and when is it ignored?
O(log n) lookups and ordered range scans. It is skipped when the column sits inside a function, selectivity is low, LIKE starts with a wildcard, or the query misses the index’s leading column.
How do you order columns in a composite index?
Equality columns first, then range or sort columns. (account_id, txn_ts) serves "account X between two dates".
How do you diagnose a slow query?
EXPLAIN ANALYZE, then look for full scans, bad row estimates and nested loops over large sets. Fix indexes, rewrite the query, refresh statistics.
Normalization vs denormalization?
3NF removes redundancy and update anomalies. Denormalize deliberately for read-heavy views, such as a materialized balance.
ACID in one line each?
Atomic: all or nothing. Consistent: constraints hold. Isolated: concurrent transactions don’t interfere. Durable: commits survive a crash through the write-ahead log.

JPA and Hibernate

What is the N+1 problem, and how do you fix it?
Loading N parents and then each lazy child collection fires N extra queries. Fix with JOIN FETCH, @EntityGraph, batch fetching or DTO projections.
LazyInitializationException: cause and proper fix?
A lazy association is touched after the session closed. Fetch what you need inside the transaction; don’t paper over it with open-in-view or EAGER everywhere.
What are the entity states?
Transient, managed, detached and removed. Dirty checking flushes changes to managed entities at commit.
Optimistic vs pessimistic locking in JPA?
@Version throws OptimisticLockException on a conflicting commit, good for low contention. PESSIMISTIC_WRITE issues SELECT ... FOR UPDATE for hot rows such as balances.
save vs saveAndFlush; flush vs commit?
save puts the entity in the persistence context; flush sends the SQL without committing; commit ends the transaction.
First-level vs second-level cache?
L1 is per EntityManager and always on. L2 is shared across sessions: fine for read-mostly reference data, risky for balances.
How do you bulk-insert 1M rows?
Enable JDBC batching (hibernate.jdbc.batch_size, order_inserts). Avoid IDENTITY IDs, which disable batching; use a pooled SEQUENCE, flush and clear every N rows, or use JdbcTemplate.batchUpdate.
How do you paginate a huge table?
OFFSET slows as it grows. Use keyset pagination: WHERE id > :lastId ORDER BY id LIMIT n.

Caching and NoSQL

Cache-aside vs write-through?
Cache-aside: read the cache, load from the DB on a miss, invalidate on write; it is the common default. Write-through: every write goes through the cache to the DB synchronously.
Eviction and stampedes?
LRU or LFU plus a TTL. Prevent a stampede on hot keys with request coalescing or jittered TTLs.
SQL or NoSQL for a given use case? HSBC
SQL for transactions, joins and strong consistency, such as the ledger and accounts. NoSQL for flexible schemas, very high write volume or key-value access, such as sessions and audit events.
Connection-pool exhaustion: symptoms and fix?
Requests hang, then time out waiting for a connection. Find long transactions and leaks (HikariCP leakDetectionThreshold), and never hold a connection across a remote call.

Coding problems from Karat rounds

Classic Karat coding gives one or two problems whose parts build on each other, and your code must pass the provided tests. Karat says algorithm-style questions suit graduates, while senior candidates get more discussion and analysis (Karat, questions explained). For a GCB-4 role, treat these as speed drills: part 1 in 15 minutes or less.

  1. Badge access (reported write-up)
    • Part 1: from ordered enter/exit records, list who entered without exiting and who exited without entering. Track a name → inside flag; an exit while outside or an enter while inside is a violation, and anyone still inside at the end never exited. O(n).
    • Part 2: from unordered (name, HHMM) records, find anyone who badged in 3+ times within one hour (inclusive) and return every time in their first such window. Group by name, sort, convert HHMM to minutes, then slide a window. O(n log n).
    • Trap: never subtract raw HHMM values. 1405 − 1315 = 90, but the real gap is 50 minutes.
  2. Domain click counts (LeetCode, Karat assessment)
    • Part 1: from "count,domain" lines, total clicks for each domain and every parent (mail.yahoo.com → yahoo.com → com). Add the count to each dot-suffix in a HashMap<String, Long>, then sort if asked. This is LeetCode 811.
    • Common follow-up: the longest run of pages two users visited in the same order, which is LeetCode 718 (maximum length of repeated subarray), O(m·n) DP. Return the pages, not just the length.
  3. Parents and children (LeetCode, Karat OA)
    • Part 1: from (parent, child) pairs, list people with zero known parents and with exactly one. For [1,3] [2,3] [3,4] [4,5] [6,5]: zero = {1, 2, 6}, one = {4}. Count parents per child over the union of all nodes. O(n).
    • Part 2: hasCommonAncestor(a, b). Build child → parents, collect a’s ancestors into a set by DFS, then walk b’s ancestors checking membership.
    • Likely part 3: the earliest ancestor, meaning the most generations away. Use BFS by levels.
  4. Words and grids (LeetCode, Indeed via Karat)
    • Part 1: the first word buildable from a string’s letters ("balloons" → "son"). Compare 26-slot letter counts per word.
    • Part 2: find a word in a grid moving only right or down, and return its cells. DFS with two directions from each matching start.
    • Part 3: several words where each cell is used once. Backtracking with a used-cell set.
  5. Basic calculator: evaluate + and −, then parentheses, then possibly variables from a map. Keep a running total, a sign and a stack for parentheses. LeetCode 224 appears in the Karat-tagged list with 811 and 718 (company-wise list).

Other families worth one drill each (widely reported, not verified here): shared courses for every pair of students, then the middle course of a prerequisite chain; a rectangle of 0s in a matrix of 1s, then many rectangles, then irregular shapes (flood fill); reaching an exit or treasure on a grid with walls (BFS); wrapping and then fully justifying text to a width.

Worked Java answer: badge access, part 2

static Map<String, List<Integer>> frequentBadgers(String[][] records) {
    Map<String, List<Integer>> byName = new HashMap<>();
    for (String[] r : records)
        byName.computeIfAbsent(r[0], k -> new ArrayList<>()).add(Integer.parseInt(r[1]));
    Map<String, List<Integer>> result = new TreeMap<>();
    for (Map.Entry<String, List<Integer>> e : byName.entrySet()) {
        List<Integer> t = e.getValue();
        Collections.sort(t);                       // HHMM order = time order
        for (int i = 0; i < t.size(); i++) {
            int j = i;
            while (j + 1 < t.size() && toMin(t.get(j + 1)) - toMin(t.get(i)) <= 60) j++;
            if (j - i + 1 >= 3) {                  // first qualifying window
                result.put(e.getKey(), new ArrayList<>(t.subList(i, j + 1)));
                break;
            }
        }
    }
    return result;
}

static int toMin(int hhmm) { return hhmm / 100 * 60 + hhmm % 100; }

On the reported sample this returns John → [830, 835, 855, 915, 930] and Paul → [1315, 1355, 1405]. The inner loop stays short: a window that doesn’t qualify holds at most two times.

How to work any Karat coding part: read the prompt and the given tests, confirm edge cases (empty input, duplicates, ties), state the plan and complexity in about a minute, code in small helpers, and run the tests early and often.

Fix-then-extend drills (the HSBC live-coding task)

HSBC’s live-coding part hands you existing backend code with failing unit tests: fix it until they pass, then enhance the same code (Glassdoor, HSBC-India). A similar Karat round elsewhere gave a large OOP codebase: fix a bug, explain and add tests, then add two features in 45 minutes (Blind, Indeed via Karat). For senior candidates Karat also shows code exhibits and asks you to spot performance or security problems (Karat).

The routine

  1. Run every test before reading any code. Read the failing assertion and stack trace, not the whole codebase.
  2. Trace from the failing test into the code, say your hypothesis aloud, make the smallest fix, rerun everything.
  3. Add a regression test for the bug and name the edge cases you would add with more time.
  4. For the enhancement: restate the requirement, write a failing test first, implement, rerun.
  5. With time left, say what you would refactor and which risks remain (concurrency, validation, money handling).

Bugs these exercises plant: scan for these first

  • Boundary errors: > vs >=, < vs <=, and inclusive time windows.
  • Money in double or int division: 350 / 10000 is 0 in integer maths. Use BigDecimal with compareTo, never equals.
  • Strings compared with ==, or Integer compared with == (cached only from −128 to 127).
  • Times kept as strings: "930" sorts after "1315" lexicographically. Parse to int, LocalTime or Instant.
  • A class used as a HashMap key without equals/hashCode, or with mutable fields in the hash.
  • Removing from a list inside for-each (ConcurrentModificationException); use removeIf or an Iterator.
  • Comparator (a, b) -> a - b overflowing on large values; use Integer.compare.
  • Null paths: map.get returning null, Optional.get(), auto-unboxing a null Integer.
  • Shared mutable state in a singleton bean: HashMap, SimpleDateFormat, instance counters.
  • @Transactional on a self-invoked or private method, or a checked exception that never rolls back.

Drill 1: account withdrawal (fix, then extend)

An HSBC round asked candidates to build a bank-account microservice (open, close, deposit, withdraw, balance) with dummy data and TDD (Glassdoor, HSBC Senior Software Engineer). Given code:

public void withdraw(String id, double amount) {
    Account a = accounts.get(id);
    if (a.getBalance() - amount > 0) {
        a.setBalance(a.getBalance() - amount);
    } else {
        throw new InsufficientFundsException(id);
    }
}

Failing tests: withdrawing the full balance should leave 0; an unknown ID should throw AccountNotFoundException; three withdrawals of 0.10 from 0.30 should leave 0.

  • Fixes: > becomes >=; a null account throws AccountNotFoundException; money moves to BigDecimal (0.30 minus three 0.10 doubles lands at about −2.8e-17); reject amounts ≤ 0.
  • Extension: add transfer(from, to, amount) that is atomic, rejects from = to, and cannot deadlock: lock both accounts in ID order. Then add a daily withdrawal limit.
  • Lead-level remark: in a real service, do this in one DB transaction with SELECT ... FOR UPDATE on both rows, ordered by ID.
public void withdraw(String id, BigDecimal amount) {
    if (amount == null || amount.signum() <= 0)
        throw new IllegalArgumentException("amount must be positive");
    Account a = Optional.ofNullable(accounts.get(id))
            .orElseThrow(() -> new AccountNotFoundException(id));
    synchronized (a) {
        if (a.getBalance().compareTo(amount) < 0) throw new InsufficientFundsException(id);
        a.setBalance(a.getBalance().subtract(amount));
    }
}

Three more drills: build each in 20 minutes

  1. Transaction history stores times as "HHmm" strings and sorts them as strings. Failing test: 09:30 must come before 13:15. Fix by parsing; extend with an inclusive time-range filter.
  2. Duplicate payment check uses a Payment class as a HashSet element without equals/hashCode, so duplicates slip through. Fix with a record; extend so the same account and amount within 5 minutes counts as a duplicate.
  3. Interest calculator computes balance × (rateBps / 10000) with int rateBps, so interest is always 0. Fix with BigDecimal and HALF_EVEN rounding; extend with monthly compounding.

Code-review exhibits: say what is wrong in 60 seconds

for (Customer c : customerRepo.findAll()) {
    List<Account> accs = accountRepo.findByCustomerId(c.getId());
    total = total.add(sum(accs));
}

Findings: loads the whole table into memory, fires N+1 queries, and has no pagination. Replace with one aggregate query or a paged DTO projection.

@GetMapping("/accounts")
public List<Account> find(@RequestParam String owner) {
    return jdbc.query("SELECT * FROM account WHERE owner = '" + owner + "'", mapper);
}

Findings: SQL injection (use a bound parameter), entities exposed directly (use a DTO), no ownership check so any caller can read any account (IDOR), and SELECT *.

@Service
public class RateCache {
    private final Map<String, BigDecimal> rates = new HashMap<>();
    private final SimpleDateFormat fmt = new SimpleDateFormat("yyyy-MM-dd");
}

Findings: a singleton bean shares a non-thread-safe HashMap and SimpleDateFormat across request threads. Use ConcurrentHashMap and the immutable DateTimeFormatter.

API-change probe Karat describes for seniors: "We need to add input fields to this API. How?" Treat the API as a contract. Optional, additive fields are backward compatible; anything breaking needs a new version, with the old one deprecated on a published date.

Lead-level design prompts (GCB-4)

These are the longer design questions a GCB-4 candidate should answer in about five minutes each; the first three were reported by HSBC candidates (Glassdoor, HSBC Senior Software Engineer). Karat Studio has a whiteboard, and the same material carries into HSBC’s own design and hiring-manager rounds.

Five-minute answer frame: requirements and numbers (1 min) → API and data model (1 min) → components and flow (1.5 min) → bottlenecks, failure modes and consistency (1 min) → security, compliance and observability (30 s).

Walk me through your current project’s architecture. HSBC
Give scale first (TPS, data volume, SLA), then the component map, one hard decision and its trade-off, one incident and what you changed, and what you would redo.
Design a bank-account microservice: open, close, deposit, withdraw, balance. HSBC
POST /accounts, POST /accounts/{id}/deposits and /withdrawals with an Idempotency-Key, GET /accounts/{id}/balance, POST /accounts/{id}/close. Keep an append-only ledger of entries plus a locked balance row, BigDecimal amounts, and a state machine where closing needs a zero balance. Publish events through an outbox and drive it test-first.
Your Spring Boot services each own a database. How do they communicate and stay consistent? HSBC
Database per service; API composition or a CQRS read model for cross-service reads; sagas plus outbox for cross-service writes. Avoid shared tables and distributed two-phase commit.
Design a fund-transfer (payments) service.
Idempotency keys, a double-entry ledger, an orchestrated saga with compensation, deduplicated events, a daily reconciliation job, limits and an audit trail. See the flow below.
Design transaction alerts (SMS, email, push).
Kafka topic per event type, one consumer group per channel, templates and user preferences, retries with backoff, a dead-letter topic, provider failover and deduplication. State a target, such as a debit alert within 5 seconds.
Design a rate limiter for a public banking API.
Token bucket per API key in Redis via an atomic Lua script, tiered limits, 429 with Retry-After. Decide per endpoint whether to fail open or closed if Redis is down.
Design month-end statements for 20M accounts.
Spring Batch with partitioned, chunked, restartable steps reading from a replica. Render PDFs asynchronously into object storage, notify when ready, and keep reruns idempotent.
Break a monolith into microservices.
Strangler-fig pattern: find bounded contexts, move a low-risk capability first behind an anti-corruption layer, sync data with CDC, run old and new in parallel and compare, and put observability in before the first cut.
Design real-time card fraud checks.
Stream processing (Kafka Streams or Flink) computing velocity and geo features; rules plus a model score returned in under 100 ms for authorization, with slower cases queued for analysts and outcomes fed back.

Fund-transfer saga

flowchart TD
    A[Client POST /transfers<br/>with Idempotency-Key] --> B[Transfer service<br/>save PENDING + outbox]
    B --> C[Debit source account]
    C -->|ok| D[Credit target account]
    C -->|fails| F[Mark FAILED]
    D -->|ok| E[Mark COMPLETED<br/>publish event]
    D -->|fails| G[Compensate:<br/>refund source]
    G --> F

A retry with the same key returns the stored result, so the customer is never debited twice.

What lifts an answer to lead level: name non-functional targets (availability such as 99.95%, RPO/RTO, p99 latency), regulatory limits (PCI DSS, data residency, audit retention), cost, and which team owns each service.
