GlobalPay — International Money Transfer Platform (HLD + LLD)

Cross-border P2P transfers: microservices HLD, priority lanes, coupon engine, card processing (3DS, fraud, chargebacks), FX, AML/KYC aur Spring Boot 3 LLD. / Payments system design case study.

1. Problem Statement

GlobalPay is an international peer-to-peer (P2P) money transfer platform inspired by Western Union that enables users across multiple countries to send funds using credit/debit cards. The system must be intelligent, personalised, and high-performance.

•Users in different countries perform cross-border transactions with varying currencies, exchange rates, and regulatory requirements. •Identify and surface priority transactions (high-value, time-sensitive, VIP users) and route them through faster processing lanes. •Coupon and discount engine must reward loyal and frequent users based on transaction history, destination, and user segment. •Credit card processing must handle international card networks (Visa, Mastercard, Amex) with 3DS, fraud detection, and chargeback management. •Latency target: < 2s UI response, < 30s settlement initiation. •Must be horizontally scalable, fault-tolerant, AML and KYC compliant.

2. High-Level Design (HLD)

2.1 Architecture Overview

GlobalPay adopts a Microservices Architecture deployed on Kubernetes with an API Gateway as single entry point. Each domain is an independent service with its own database, communicating via REST (sync) and Apache Kafka (async event streaming).

2.2 Priority Transaction System

Priority scoring determines which transactions use the fast lane (target <5s settlement) vs standard queue.

PLATINUM90–100VIP user OR amount >$10,000 OR business accountDedicated thread pool, skip queue
GOLD70–89Premium user OR amount $1,000–$10,000High-priority Kafka partition
SILVER50–69Regular user ≥3 TXN/month OR $200–$999Standard queue, prioritised
STANDARD0–49New or infrequent user, low amountStandard processing queue

2.3 Coupon & Reward Engine

•Rule-based triggers: First international transfer, milestone TXNs (5th, 10th, 25th), birthday month. •Corridor offers: Users on high-frequency corridors (US→India, UK→Philippines) get corridor-specific coupons. •Dynamic fee discounts: 0% fee when 30-day volume exceeds threshold; tier-based percentage discounts. •Referral coupons: Sender gets 50% fee discount when referred user completes first transaction. •Expiry management: 7–30 day TTL; 48h reminder notification before expiry.

3.2 Priority Engine

Java

// PriorityEngine.java  -  Scores each transaction 0–100
@Service
@RequiredArgsConstructor
public class PriorityEngine {

    private static final String CACHE_PREFIX = "txn:count:";

    private final RedisTemplate<String, Integer> redis;
    private final UserRepository                 userRepo;
    private final TransactionRepository          txnRepo;

    public int score(String userId, BigDecimal amount) {
        User user  = userRepo.findById(userId).orElseThrow();
        int  score = 0;

        // -- Amount scoring (max 40 pts) -----------------------------------
        if (amount.compareTo(BigDecimal.valueOf(10_000)) >= 0) score += 40;
        else if (amount.compareTo(BigDecimal.valueOf(1_000)) >= 0) score += 25;
        else if (amount.compareTo(BigDecimal.valueOf(200))   >= 0) score += 10;

        // -- User-tier scoring (max 30 pts) --------------------------------
        score += switch (user.getTier()) {
            case VIP      -> 30;
            case PREMIUM  -> 20;
            case STANDARD -> 10;
            default       -> 0;
        };

        // -- Monthly TXN frequency (max 20 pts) - Redis-cached 1h ---------
        Integer count = redis.opsForValue().get(CACHE_PREFIX + userId);
        if (count == null) {
            count = txnRepo.countByUserIdSince(userId,
                    LocalDate.now().minusMonths(1));
            redis.opsForValue().set(CACHE_PREFIX + userId, count,
                    Duration.ofHours(1));
        }
        if (count >= 10) score += 20;
        else if (count >= 3) score += 10;

        // -- Business account bonus (max 10 pts) ---------------------------
        if (user.getAccountType() == AccountType.BUSINESS) score += 10;

        return Math.min(score, 100);
    }
}

3.3 FX Service with Redis Caching & Circuit Breaker

Java

// FxService.java  -  Exchange rate provider with resilience
@Service
@RequiredArgsConstructor
public class FxService {

    private final RedisTemplate<String, FxRate> redis;
    private final ExternalFxClient              fxClient;

    @CircuitBreaker(name = "fxService", fallbackMethod = "cachedRate")
    @Retry(name = "fxService")
    public FxRate getRate(String from, String to) {
        String key   = "fx:" + from + ":" + to;
        FxRate cached = redis.opsForValue().get(key);
        if (cached != null) return cached;

        FxRate rate = fxClient.fetchRate(from, to);
        redis.opsForValue().set(key, rate, Duration.ofSeconds(30));
        return rate;
    }

    // Fallback: return last known cached rate on external API failure
    public FxRate cachedRate(String from, String to, Exception ex) {
        FxRate stale = redis.opsForValue().get("fx:" + from + ":" + to);
        if (stale != null) return stale;
        throw new FxUnavailableException("FX rate unavailable for " + from + "/" + to);
    }

    // Warm-up job: refresh top corridors every 30 seconds
    @Scheduled(fixedDelay = 30_000)
    public void refreshTopCorridors() {
        List.of("USD:INR", "USD:PHP", "GBP:EUR", "USD:MXN",
                "USD:NGN", "GBP:USD", "EUR:GBP", "USD:CAD")
            .forEach(corridor -> {
                String[] parts = corridor.split(":");
                FxRate   rate  = fxClient.fetchRate(parts[0], parts[1]);
                redis.opsForValue().set("fx:" + corridor, rate,
                                       Duration.ofSeconds(60));
            });
    }
}

3.4 Coupon Service - Strategy Pattern

Java

// CouponStrategy.java - Contract for all coupon evaluators
public interface CouponStrategy {
    Coupon evaluate(String userId, TransactionRequest req);
}

// CouponService.java - Picks the best applicable coupon
@Service
@RequiredArgsConstructor
public class CouponService {

    private final List<CouponStrategy> strategies;
    private final CouponRepository     couponRepo;

    public CouponResult apply(String userId, TransactionRequest req) {
        List<Coupon> applicable = strategies.stream()
            .map(strategy -> strategy.evaluate(userId, req))
            .filter(Objects::nonNull)
            .filter(c -> !couponRepo.isUsedByUser(c.getCode(), userId))
            .sorted(Comparator.comparing(Coupon::getDiscountRate).reversed())
            .toList();

        if (applicable.isEmpty()) return CouponResult.none();

        Coupon best = applicable.get(0);
        couponRepo.markUsed(best.getCode(), userId);
        return CouponResult.of(best);
    }
}

@Component
public class CorridorCouponStrategy implements CouponStrategy {
    private static final Set<String> TOP_CORRIDORS =
        Set.of("USD:INR", "USD:PHP", "GBP:NGN", "EUR:USD");

    public Coupon evaluate(String userId, TransactionRequest req) {
        String corridor = req.getSourceCurrency() + ":" + req.getTargetCurrency();
        return TOP_CORRIDORS.contains(corridor)
            ? Coupon.percentDiscount("CORRIDOR-50", 50) : null;
    }
}

@Component
public class LoyaltyCouponStrategy implements CouponStrategy {
    public Coupon evaluate(String userId, TransactionRequest req) {
        long count = txnRepo.countByUserId(userId);
        if (count == 9)  return Coupon.percentDiscount("LOYALTY-10TH", 25);
        if (count == 24) return Coupon.percentDiscount("LOYALTY-25TH", 50);
        if (count == 49) return Coupon.zeroFee("LOYALTY-50TH");
        return null;
    }
}

5.1 Outbox Pattern - Guaranteed Kafka Delivery

Java

// OutboxPoller.java  -  Transactional relay from DB to Kafka
@Component
@RequiredArgsConstructor
@Slf4j
public class OutboxPoller {

    private final OutboxRepository                      outboxRepo;
    private final KafkaTemplate<String, String>         kafka;

    @Scheduled(fixedDelay = 1_000)   // poll every 1 second
    @Transactional
    public void relay() {
        List<OutboxEvent> pending =
            outboxRepo.findTop50ByProcessedFalseOrderByCreatedAtAsc();

        pending.forEach(event -> {
            try {
                kafka.send(event.getTopic(), event.getId().toString(),
                           event.getPayload()).get();       // sync send
                event.setProcessed(true);
                log.debug("Relayed outbox event [{}] to topic [{}]",
                          event.getId(), event.getTopic());
            } catch (Exception ex) {
                log.error("Failed to relay outbox event [{}]: {}",
                          event.getId(), ex.getMessage());
                // will retry on next poll
            }
        });

        outboxRepo.saveAll(pending);
    }
}

// AsyncConfig.java - Priority-based thread pools
@Configuration @EnableAsync
public class AsyncConfig {

    @Bean("platinumExecutor")
    public Executor platinumExecutor() {
        return buildPool("platinum-", 10, 20, 50);
    }

    @Bean("goldExecutor")
    public Executor goldExecutor() {
        return buildPool("gold-", 15, 40, 200);
    }

    @Bean("standardExecutor")
    public Executor standardExecutor() {
        return buildPool("standard-", 30, 80, 500);
    }

    private Executor buildPool(String prefix, int core, int max, int queue) {
        ThreadPoolTaskExecutor e = new ThreadPoolTaskExecutor();
        e.setCorePoolSize(core);
        e.setMaxPoolSize(max);
        e.setQueueCapacity(queue);
        e.setThreadNamePrefix(prefix);
        e.setWaitForTasksToCompleteOnShutdown(true);
        e.initialize();
        return e;
    }
}
